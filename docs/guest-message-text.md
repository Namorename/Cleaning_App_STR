# Сообщение гостя в задании из чата «на лету» (11.11)

Слово владельца 11.11: задание из чата показывает само сообщение гостя, на которое сработала метка.
Текст сообщения по-прежнему **не хранится нигде** — ни в базе, ни в журналах, ни в кэше на диске. Его
читают из Hostaway в момент просмотра, как текст отзыва в «Все отзывы» (`guest-review-text`).

Миграция `20261111140000_guest_message_text.sql`, функция `supabase/functions/guest-message-text`.

## 1. Что видно и где

- **Блок «Сообщение гостя»** с кнопкой «Показать сообщение из Hostaway». Само ничего не грузится,
  только по нажатию. Где стоит:
  - панель: страница задания из чата и карточка чата в «Гостях»;
  - телефон: экран задания из чата, у главного техника и у менеджера, вошедшего с телефона.
- **Что показывает:**
  - сообщение, на котором сработала метка (пометка «отмечено»), и до двух соседних сообщений гостя в
    пределах двух часов от него — всего не больше трёх;
  - у каждого дату и время по часам компании (Прага), число вложений;
  - пометку «Текст не хранится у нас: он прочитан из Hostaway только для этого просмотра».
- **Ответы компании гостю не показываются никогда**, только слова гостя.
- **Состояния**, у каждого свои слова (`problems.guestMessage.*`, ru/en/cs):

  | Состояние | Слова | «Повторить» |
  |---|---|---|
  | загрузка | «Загружаем сообщение из Hostaway…» | — |
  | показано | сообщения, дата и время, пометка | — |
  | срок вышел | «Сообщение недоступно по сроку хранения» | нет |
  | Hostaway недоступен | «Hostaway недоступен, попробуйте позже» | да |
  | нет прав | «Сообщение гостя видят только менеджер и главный техник» | нет |
  | лимит | «Слишком много просмотров за 10 минут, попробуйте позже» | да |
  | нет в Hostaway | «Hostaway не нашёл это сообщение» | нет |
  | прочее (сеть) | «Не удалось загрузить сообщение» | да |

- **Права:**

  | Кто | Что |
  |---|---|
  | менеджер, администратор | по заданию и по карточке «Гостей» |
  | главный техник | по заданию (раздела «Гости» у него нет) |
  | техник, горничная, отключённый сотрудник | ничего: на телефоне кнопки нет, функция отказывает |

  Телефон показывает кнопку тем, кому сервер назвал гостя в «Гость и проживание»
  (`problem_guest_origin`). Роль решает сервер, приложение её не проверяет.

## 2. Какие данные нужны и где они лежат

Чтобы найти сообщение в Hostaway, нужны три вещи. Ни одна из них не текст:

| Что | Где | Срок |
|---|---|---|
| номер разговора в Hostaway | `signal_findings.external_conversation_id` (карточка) | у задания — до конца связи; у карточки без задания — 30 дней после решения, не дольше 89-го дня |
| номер сообщения в Hostaway | `guest_signals.external_id` | у задания — до конца связи; без задания уходит при обрезке |
| ключ сообщения (HMAC номера под `GUEST_SIGNAL_KEY_SECRET`) | `guest_signals.external_key` | у задания — до конца связи; без задания 90 дней от сообщения (`purge_signal_data`) |

- **Поиск.** Функция берёт разговор целиком (GET `conversations/{id}/messages`) и находит сообщение
  по номеру. Если номера уже нет, она считает HMAC номера каждого сообщения гостя и сравнивает с
  ключом. Сам ключ без секрета ни к чему не ведёт.
- **Связь задания** (`signal_findings.task_link_ends`). Ставится триггером `signal_findings_task_link`
  в момент, когда карточка становится заданием. Равна ночи, когда очистка стирает имя гостя: выезд +
  91 день (`raw.purge_guest_data`, 05:55 UTC). Пока связь жива:
  - `cut_signal_stay_links` не отвязывает бронь, точные даты, номер и время сообщения;
  - `purge_signal_data` не стирает ключ и номер сообщения;
  - `purge_guest_message_links` не стирает ключ разговора у сообщения и номер разговора на карточке;
  - строка разговора в очереди чатов (`raw.signal_message_queue`) не удаляется.
- **В ночь конца связи** каждое из этого уходит своим ночным заданием, как раньше: обрезка в 05:00,
  ключи в 05:05, разговор в 05:20, имя в 05:55. После этого функция отвечает «срок вышел».
  - Если бронь сократили после создания задания, связь уходит в ночь стирания имени по новому выезду:
    обрезка проверяет то же условие, что и очистка имени.
  - Обрезка стирает и саму дату `task_link_ends`: иначе по ней (выезд + 91) читался бы точный день
    выезда, а после обрезки по правилу 17.10 остаётся только месяц.
- **Кого правило не касается:**
  - карточки без задания отвязываются как раньше;
  - задания, созданные до миграции (у них нет даты), не трогаются и не восстанавливаются;
  - если проживание было уже обрезано к моменту создания задания, связь не появляется;
  - задание, снятое как «ложное срабатывание», теряет дату, и следующая ночь его обрезает.
- **Отзывы.** Правило то же: у задания из отзыва бронь и точные даты тоже живут до стирания имени.
  Поэтому «Гость и проживание» показывает имя и дни и после решения.

## 3. Функция `guest-message-text`

- **Вход:** POST `{"problem_id": "<uuid>"}` или `{"finding_id": "<uuid>"}` с токеном сессии.
- **Порядок проверок:**
  1. Origin: страницы панели (`_shared/panel-origin.ts`, общий с `guest-review-text`) или никакого
     (телефон). Чужой странице — 403 без заголовков CORS.
  2. Токен → профиль: роль, компания, активность (из `profiles`, не из токена).
  3. Счётчик `take_message_text_read`: 60 чтений на человека за 10 минут, считается до поиска.
     Сверх лимита — 429 с `Retry-After`.
  4. `guest_message_target` (только `service_role`): права по роли, компания, задание из чата, сроки.
     Отвечает только номерами, никогда текстом.
  5. GET разговора из Hostaway. Отказ — 502 «Hostaway недоступен»; разговора нет — 404.
- **Ответ:** `{data: {messages: [{sent_at, text, attachments, is_flagged}]}}`, `Cache-Control:
  no-store`. Ни имени гостя, ни брони, ни объекта, ни номеров PMS.
- **Память:** ответ держится в памяти экземпляра 3 минуты (`cache.ts`), ключ начинается с компании.
  На диск ничего не пишется.
- **Журнал:** одна строка на запрос — код исхода и время в мс (`guest-message-text ok in 412 ms`). Ни
  текста, ни имени, ни номеров.
- **Секреты те же, что у `guest-review-text`:** доступ к Hostaway и `GUEST_SIGNAL_KEY_SECRET`. Новых
  нет.
- `verify_jwt = false` (`supabase/config.toml`): токен проверяет сама функция, как у
  `guest-review-text`.

## 4. Приложения

- **Панель** (`apps/web/src/features/problems/guest-message.tsx`, `use-guest-message.ts`). Запрос идёт
  через TanStack Query: только по нажатию, без повторов, держится 3 минуты в памяти страницы. Панель
  ничего не сохраняет на диск.
- **Телефон** (`apps/mobile/src/features/problems/guest-message-block.tsx`, `use-guest-message.ts`).
  Ответ живёт в состоянии экрана, а не в запросе: запросы телефона сохраняются на диск. Ответ,
  пришедший после закрытия экрана, отбрасывается. Тест проверяет, что сохраняемый кэш текста не
  содержит.
- **Общее** (`packages/shared/src/problems/guest-message.ts`): разбор ответа, состояние по ключу
  отказа, дата и время.
