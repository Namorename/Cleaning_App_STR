# Задания из отзывов гостей — самопроверка и риски

2026-10-17, к `docs/reviews-to-tasks.md` и черновику
`supabase/migrations/20261017110000_reviews_to_tasks.sql`. Две части:

1. мой разбор дизайна как критика: противоречия, RLS, гонки, стоимость, GDPR;
2. независимый обзор — новый агент `ecc:database-reviewer`. Ему дали только черновик, документ и
   существующие миграции; он только читал и ничего не запускал.

Всё исправленное перепроверено на стенде: 38 проверок черновика, 6 проверок отката и отказ отката
при существующих заданиях из отзывов.

## 1. Разбор как критик

### Исправлено в черновике

| Находка | Сценарий | Что сделано |
|---|---|---|
| **Пуш не доходит** (ловушка в нынешнем коде) | `push_on_problem_reported`: `h.id <> new.reported_by` при пустом авторе даёт null — ни один главный техник не получает пуш о задании из отзыва | переопределено через `is distinct from`; проверка «пуш главному технику доходит» |
| **История стала бы заданиями** | еженедельное перечитывание 100 дней сохранило бы тексты старых отзывов, разбор нашёл бы в них «поломки» прошлого лета | тексты хранятся только у отзывов, присланных после `notice_published_at`; индекс разбора смотрит на сохранённый текст, а не на флаги; проверка «история без текста» |
| **Цикл по изменяющему CTE** | в `apply_review_findings` `for … in with … insert … returning` — курсор с INSERT в WITH падает | сначала вставка с `array_agg(id)`, затем `foreach` |
| **Повтор отзыва в порции** | две одинаковые строки в одной порции — `on conflict do update` «affect row a second time» роняет загрузку | `distinct on (external_id)` с последней `external_updated_at` |
| **Разбор не мог вести журнал** | `raw` не открыт через PostgREST, `apply_review_findings` журнал не пишет — потолку вызовов модели нечего считать | `log_review_run()` и `review_model_calls_left()` (только `service_role`); проверки «0 при выключенной модели», «остаток считает сегодняшние вызовы» |
| **Задание без места** | одобренная находка без объекта дала бы задание, которое `assign_problem` не назначит (`problemNoProperty`) | `create_review_problem` отказывает `serverErrors.reviewFindingNoPlace` |
| **Место на обслуживании** | находка об объекте в `maintenance` молча уходила в «без задания» | `no_task` — только архив; обслуживание идёт к менеджеру и никогда не идёт в «сразу» |
| **Менеджер не мог поправить правила** | находка, отброшенная по уверенности или принятая за починенную, не поднималась в задание | одобрение работает для `candidate`, `dropped`, `already_fixed` |
| **Нет ручного пути** | «Создать задание из отзыва» без модели | `add_review_finding` (чтец `manual`) через тот же `approve` |
| **Срочный пуш ночью** | одобрение в 23:00 «высокой» поломки будило бы главного техника | у задания из отзыва срочный пуш только для «безопасности», остальное ждёт 07:00 |

### Противоречия в документе — исправлены

- **Нагрузка на Hostaway:** в «Коротко» было «1–5 запросов в сутки», а по §5 выходит 3–8 (по
  воскресеньям перечитывание 100 дней) — исправлено на 3–8.
- **Отступления от плана 16.10** перечислены явно:
  - `report_problem` не переносим во внутреннюю функцию;
  - связь задания и находки — в `review_findings.problem_id`, а не `problems.review_finding_id`;
  - адаптер спрашивает комнату сам;
  - время запуска 06:00 и 06:20 вместо 03:25 и 03:40.

### Остаётся рисками (осознанно)

| Риск | Почему остаётся | Чем держим |
|---|---|---|
| **Две вставки в `problems`** (`report_problem` и `create_review_problem`) | центральный RPC телефона не трогаем | тест шага 1: оба пути дают одинаковые журнал и пуш; общий `validate_problem_text` |
| **Окно, когда клиенты не готовы к заданию без автора** | панель и телефон сегодня падают на `reported_by: null` | выключатель `tasks_enabled` (только админ) включается после распространения OTA шага 1; до него ни одна функция задание не создаёт |
| **Обезличивание проверяется только в Edge Function** | база не может проверить, что в тексте нет имён | тесты `redact.ts` на выдуманных фразах на четырёх языках; проверка ответа модели («в `summary` нет имён из списков»); фрагмент виден только менеджеру |
| **Заголовок задания хранится бессрочно** | `problems` не чистятся, а заголовок — формулировка модели | правило ответа: только описание неисправности, без имён и цитат; заголовок не персональные данные, если правило соблюдено |
| **`review_facts` у техника** | дата выезда + объект указывают на бронь (псевдоним) | решение 3 разрешает дату выезда; канала с оценкой и текста у техника нет |
| **Потолок модели требует, чтобы Edge Function бронировала** | база выдаёт бронь под замком (`reserve_review_model_calls`), но не видит вызовов, сделанных без брони | тест функции «ни одного вызова без брони»; второй забор — лимит расходов в консоли Anthropic (ставит владелец) |
| **Нет кнопки «удалить данные гостя»** | первая версия | запрос гостя — разовая запись по слову владельца (`delete from guest_reviews where external_reservation_id = …`) |
| **Скрытые на площадке отзывы** (`isHidden`) | поломка остаётся поломкой | загружаются и разбираются как все (вопрос владельцу) |
| **Точность после включения «сразу»** | автомат сам себе метки не ставит | отменённые менеджером авто-задания считаются решениями «нет»; на экране настроек — доля отмен |
| **У заданий горничных нет вида** | дубль против них не определить автоматически | любое открытое задание на месте → решает менеджер; категория у заданий горничных — вне первой версии |
| **Тесты ветки** | по условию задачи тесты не менялись | `table_grants.sql` упадёт на новых таблицах, `db reset` — на страже; в этой ветке `test:rls` не запускать; при реализации — `supabase/tests/reviews_to_tasks.sql` и строки матрицы |
| **Бронь на несколько комнат** | в выборке 17.10 у всех броней зданий одна комната | адаптер: больше одной комнаты → задание на здание |

## 2. Независимый обзор

**Итог рецензента: CRITICAL и HIGH нет.** Права и RLS выдержали проверку по существующим миграциям:
- явные `revoke` у всех новых функций, у внутренних — и у `service_role`;
- кнопки менеджера проверяют `is_manager()` и компанию;
- главный техник в `is_manager()` не входит;
- переписанный пуш верен;
- с пустым `reported_by` корректно работают политики, `report_problem`, `update_problem`, чат,
  журнал, зеркало статуса, `assign_problem` и `analytics_problem_rows`;
- откат удаляет всё.

Найдено 15 пунктов уровня MEDIUM и LOW — логические пробелы и пути сбоя. Ниже — что с каждым
сделано. После правок: черновик 38 из 38, откат 6 из 6, отказ отката при заданиях из отзывов
проверен.
