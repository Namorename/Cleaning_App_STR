Первая таблица в `public` с identity-ключом или `serial` отдаст любому вошедшему `setval` на свой счётчик: сдвинуть его на занятое значение и уронить вставки дублем ключа; `revoke all on table` последовательность не трогает. Сейчас последовательностей в `public` нет, дыра спящая. Нужно: `alter default privileges for role postgres in schema public revoke all on sequences from authenticated;` и расширить проверку default ACL в `supabase/tests/table_grants.sql` с типа `r` на `r` и `S`. **Находки выката окна 2 чата (2026-09-24, `wf_7d5bfd21-885`, предполёт `wf_0807b286-31a`) — каждая отдельной миграцией вперёд, в груз окна 2 не входили:** (1) **повтор медиа-RPC не держит своего владельца** (решение владельца: в F13). Первый поиск `add_task_media` сравнивает `v_media.step_id <> p_step_id` (`20260918170000:94`); у строки поломки или сообщения `step_id` пуст, сравнение даёт `NULL`, отказ не срабатывает, и тот же автор при повторе того же id получает строку чужого владельца — после окна 2 и строку сообщения. ## Перед запуском

Предзапусковый чек-лист (заведён 2026-09-23); запуск — день, когда горничные
начинают работать в приложении по-настоящему. А и чистка журнала выкачены
окном 3 2026-09-25, Б — проект (п.7 «ДО»).

- [x] **А. `internal_notes` видны горничной — блокер запуска.** Выкачено окном
  3 2026-09-25 (M1 → панель → M2, `docs/window3-plan.md`). Колонка
  `properties.internal_notes` помечена «Office only. Never leaves the manager
  panel» (`20260905092000_cleaning_window.sql:99-100`), но политика
  `active staff read properties` фильтрует только строки, а прав на колонки в
  схеме нет. Любая активная горничная своим токеном и публичным ключом из бандла
  читает `GET /rest/v1/properties?select=internal_notes` по всем объектам
  компании. Телефон колонку не спрашивает, дыра — на уровне API (состояние до
  выката). **План миграции — отдельная таблица только для менеджера:**
  - **M1** — `public.property_internal_notes (property_id pk, host_id, notes,
    updated_at)`. Внешний ключ `(host_id, property_id) →
    properties(host_id, id) on delete cascade` — только он, второй ключ по
    одному `property_id` дал бы PostgREST два пути и `300` на эмбеде. Политика
    `for all` с `is_manager() and host_id = current_host_id()`; `revoke all` и
    точечные гранты; строка в матрице `supabase/tests/table_grants.sql`;
    перенос непустых заметок.
  - **Панель** — `internal_notes` уходит из `DETAIL_COLUMNS` и схемы карточки.
    Заметку читает отдельный читатель (в `READERS` сторожа), пишет запись
    «пусто — удалить строку, иначе upsert по `property_id`».
  - **M2** — `do`-блок, который роняет миграцию, если хоть одна непустая
    заметка не перенесена, и `alter table public.properties drop column
    internal_notes`.
  - **Порядок выката:** M1 в облако и проверка грантов → панель в `main` →

    после M2. Телефону ничего не нужно: колонку он не читает, `select=*` нет
    нигде.
  - **Права на колонки не подходят:** горничная и менеджер — одна роль БД
    `authenticated`. Такой грант отнял бы колонку и у менеджера и уронил бы
