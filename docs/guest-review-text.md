# Текст отзыва «на лету» и фильтры «Все отзывы»

Задача владельца 04.11. Две части разной судьбы:

- **Фильтры «Все отзывы»** — только панель, без нового бэкенда: читают те же
  `guest_signals` под той же RLS. Ветка `guest-reviews-1104`, в `main` идут
  сразу после проверок.
- **Текст отзыва из Hostaway** — новая функция `guest-review-text` и маленькая
  миграция `20261104200000_review_text_reads.sql`. Ветка
  `guest-review-text-1104` поверх фильтров. **Не выкачено**: деплой функции и
  `db push` — только словом владельца, панель с кнопкой — вместе с ними.

## 1. Фильтры

Раньше вкладка читала 200 новейших отзывов из 5 123. Теперь страница по 50 с
точным числом, все условия — на сервере (`fetchReviewPage`,
`apps/web/src/features/guest-signals/api.ts`):

| Фильтр | Условие PostgREST |
|---|---|
| Канал (Airbnb, Booking.com, Vrbo) | `channel=in.(…)` |
| Объект (листинги, архивные помечены) | `property_id=in.(…)` |
| Оценка от / до; «Низкие (6 и ниже)» | `rating=gte./lte.` |
| Выезд с / по (месяцы) | `departure_date=gte.<первое>&departure_date=lt.<первое следующего>` |
| Есть текст отзыва / приватный комментарий / только скрытые | `has_public_text`, `has_private_text`, `is_hidden` |
| Низкая оценка по категории (одна или любая) | `category_ratings->cat=lte.6`, «любая» — `or=(…)` по девяти |
| Находки: найдено, принято, отклонено, привязано | `findings:signal_findings!inner(status)` + `findings.status=in.(…)` |

- Период — в месяцах: у обрезанного проживания от дат остаётся месяц
  (`cut_signal_stay_links`), выбор дня обманул бы.
- «Низкие» — 6 из 10 и ниже: у Airbnb это три звезды и меньше (оценки 2/4/6/8/10),
  у Booking.com — своя шкала 1–10. На 04.11 таких 437 из 5 123.
- Сравнение `->` идёт по JSON-числам: на облаке `category_ratings->'cleanliness' <=
  '6'::jsonb` и числовое сравнение дали одно и то же (371 = 371).
- Вкладка и фильтры — в адресе, как на «Уборках» (`useAddressState`): вкладка —
  шаг истории, фильтр — на месте. Одна кнопка «Сбросить фильтры»; пусто —
  «По этим фильтрам отзывов нет.» с той же кнопкой.
- Права не менялись: страницу открывают менеджер и админ (`proxy.ts`), строки
  отдаёт RLS `guest_signals` (менеджер своей компании).

**Производительность** (EXPLAIN ANALYZE):

| База | Строк | Худший запрос страницы | Счётчик |
|---|---|---|---|
| облако (только чтение, без RLS) | 5 123 | ≈ 3 мс (первый холодный — 215 мс) | — |
| временная, под RLS менеджера | 6 000 | 10 мс | 1,3 мс |
| временная, под RLS менеджера | 50 000 | 32–50 мс | 8 мс |
| то же + индекс ниже | 50 000 | 3 мс (первая), 6 мс (последняя) | 7 мс |

Индекс сейчас не нужен. Когда отзывов станет больше ~20 000 или первая страница
станет медленнее 50 мс, — проект миграции (не применять без слова):

```sql
create index guest_signals_review_list_idx
  on public.guest_signals (host_id, submitted_at desc, id desc)
  where kind = 'review';
```

## 2. Текст отзыва «на лету»

**Зачем.** Тексты хранятся только у проживаний с заездом не раньше границы
(04.11). У остальных 5 000+ отзывов есть оценки, но нет слов. Менеджеру иногда
нужно прочесть оригинал — как в Hostaway, без обезличивания.

**Как устроено.**

1. В «Все отзывы» у отзыва без хранимого текста, но с текстом в Hostaway
   (`has_public_text` / `has_private_text`) — кнопка «Показать текст из Hostaway».
2. Панель зовёт функцию `guest-review-text` с **нашим** id отзыва
   (`guest_signals.id`) и сессией менеджера.
3. Функция:
   - проверяет токен в Auth, роль и компанию — по `profiles` (активный менеджер
     или админ), не по токену;
   - считает чтение (`take_review_text_read`, 30 за 10 минут на человека) —
     до любого поиска;
   - находит отзыв своей компании (`host_id` вызывающего) и вида `review`;
   - id отзыва в Hostaway после обрезки не хранится (решение 18.10), поэтому
     ищет по ключу: берёт у Hostaway отзывы за месяц отзыва ± день
     (`reviews?type=guest-to-host&submittedAtStart=…&submittedAtEnd=…`, только
     GET, ≈ 380–450 штук, одна страница) и сверяет HMAC
     `hostaway:review:<id>` каждого с хранимым `external_key`;
   - отдаёт публичный текст, приватный комментарий и комментарии по категориям.
4. Панель держит ответ только в памяти страницы (React Query, без сохранения,
   10 минут после закрытия строки), не повторяет запрос сама.

**Что не показывается и не хранится.**
- Имя гостя, бронь, название объекта и любые id Hostaway в ответ не идут.
- Текст не пишется ни в базу, ни в журнал функции, ни в ошибку: в журнал — одна
  строка `guest-review-text <код> in <мс>`; ошибка Hostaway (её сообщение может
  цитировать ответ) — только кодом `source_unavailable`; неожиданная — только
  именем класса. Sentry в панели и функциях нет. Ответ — `Cache-Control: no-store`.
- В базе — только счётчик: человек, окно 10 минут, число; старше суток стирается.

**Чем закрыты злоупотребления.**

| Риск | Защита |
|---|---|
| чужая компания | отзыв ищется по `host_id` вызывающего из `profiles` |
| не тот человек | только активный менеджер или админ; уборщица, техник, главный техник — 403 |
| перебор id | id — наш uuid, проверяется форма; PMS id не принимается; чтение считается до поиска |
| выкачивание текстов | 30 чтений за 10 минут на человека (счётчик в базе, общий для всех экземпляров функции); без счётчика функция не читает (503) |
| нагрузка на Hostaway | 1–2 GET на чтение, темп клиента 15 запросов за 10 с, токен один на экземпляр функции |
| истёкший отзыв | ключ `purged:` — 410, Hostaway не спрашивается |

**Ограничения.**
- Отзыв, которого Hostaway больше не отдаёт (удалён), — «Этого отзыва больше нет
  в Hostaway».
- Через 18 месяцев ключ стирается (`purge_signal_data`), текст больше не найти.
- На одно чтение функция держит в памяти тексты всех отзывов месяца (до ~450), не
  отдаёт и не хранит их.
- `verify_jwt = false` (как у `manage-staff` и `api-keys`): предполётный OPTIONS
  браузера идёт без токена; токен проверяет сама функция.
- `submittedAtEnd` Hostaway понимает (проверено 04.11 одним GET: октябрь 2026 —
  378 отзывов, ровно столько, сколько в базе за пражский октябрь); фильтра по
  объекту (`listingMapId`, `listingId`) у списка отзывов нет — он молча
  игнорируется, поэтому окно — весь месяц компании. Если бы конец окна
  игнорировался, поиск остался бы верным (по ключу), но листал бы хвост до сегодня.
- Окно счётчика фиксированное (по 10 минут): на стыке двух окон можно прочесть до
  60 подряд. Для двух человек в офисе этого хватает; скользящее окно — если понадобится.
- Один клиент Hostaway на экземпляр функции: два одновременных чтения могут не
  выдержать паузу 667 мс между запросами; 429 Hostaway гасит их повтором с отступом.
  У каждого холодного экземпляра свой токен Hostaway.
- Без секретов функция не поднимается (как `api-keys`): панель увидит сетевую ошибку.

**Ревью** (один независимый, только чтение; CRITICAL/HIGH нет):
- фильтры — «все объекты отмечены» отбрасывали отзывы без объекта (исправлено:
  весь список = без фильтра, как в «Аналитике»); строка «1–50 из …» при листании,
  фокус после сброса, месяц из ссылки вне списка (исправлено);
- текст — после ошибки не было повтора (добавлена кнопка «Попробовать снова»,
  прочитанный текст показывается без повторного щелчка); миграция без
  `lock_timeout` и с ключом на `auth.users` (теперь `public.profiles`, как у
  `raw.push_outbox`); предел тела читался после буферизации (теперь потоком, как
  у `mcp`).

## 3. Выкат (по словам владельца, по порядку)

1. **Фильтры** — `git push origin HEAD:main` с конца фильтров (слово «пушим» дано
   04.11). Схемы не меняют, OTA не нужна.
2. **Миграция** `20261104200000` — `db push` с заставой (голова облака
   `20261102100000`, сухой прогон называет ровно этот файл), не в 03:00–04:40 UTC.
   Проба после: таблица `raw.review_text_reads` есть, прав у `authenticated` и
   `anon` нет, функция `take_review_text_read` — только `service_role`.
3. **Функция** — `npx supabase functions deploy guest-review-text` (секреты уже
   есть: `GUEST_SIGNAL_KEY_SECRET`, Hostaway, Supabase). Проверки без ключей:
   OPTIONS 204, GET 405, POST без токена 401.
4. **Панель с кнопкой** — `git push origin HEAD:main` с конца ветки
   `guest-review-text-1104`. Не раньше 2–3: без функции кнопка отвечает ошибкой.
5. Проверка владельцем: открыть «Все отзывы», у старого отзыва «Показать текст
   из Hostaway».

## 4. Откат

- Панель: `git revert` коммита кнопки (и при нужде — коммита фильтров), push main.
- Функция: `npx supabase functions delete guest-review-text`.
- Миграция (после удаления функции): `drop function public.take_review_text_read(uuid);
  drop table raw.review_text_reads;` через `db query --linked`, затем
  `npx supabase migration repair --status reverted 20261104200000 --linked`.
