# Правки панели и роль Reception (CORE), 19.11

Запрос владельца 19.11 (метка CORE, ответы в диалоге той же сессии). Ветка `panel-edits-1119` от
`main` `5461fe0` (после выката этапа 3 досок). Слова на выкат пока нет.

## Что просили

1. Менеджер меняет и переименовывает **любое** задание, в том числе отчёты горничных и техников.
2. Страница задания: описание и тексты сливаются — выделить.
3. Вкладка «Гости»: карточка — одна длинная колонка, всё сливается; разнести по сторонам, читать
   разделами.
4. Настройка: отдельно выключить задания из чатов и задания из отзывов. Ответ владельца
   «Источник полностью стоп»: чаты выключены — переписки не читаются совсем (и «Качество объектов»
   из чатов тоже); отзывы выключены — только задания, оценки и качество идут дальше.
5. Роль Reception: всё, что менеджер, но не видит досок менеджеров (только доску техников —
   «Задания»), не видит «Команду», из настроек — личные разделы и «Процесс»; «Компания» и API
   скрыты и закрыты на сервере.

## Решения

### 1. Правка задания

- Новая функция `edit_problem_text(p_id, p_title, p_description default null)`: офис (через
  `problem_for_manager`, значит и Reception), любая строка своей компании, любой статус и архив.
  `p_description` null — описание не трогаем; пустая строка — стираем. Новый заголовок снимает
  переводы `title_i18n` (слова модели или категории больше не те), тот же — оставляет. Категория
  остаётся: она для статистики.
- Журнал задания (`problem_events`) не пишет правку: новый вид события сломал бы старые клиенты,
  которые читают журнал по закрытому списку видов.
- Паритет API: `planned`, право `tasks:update`, как соседние функции менеджера.
- Только панель: кнопка «Изменить» в шапке карточки отчёта, окно с заголовком и описанием.

### 2–3. Читаемость

- Общий `components/detail-section.tsx`: тихая подпись раздела над содержимым полного цвета.
- Страница задания: в шапке карточки объект, кто и когда; дальше «Описание» (крупнее, на своей
  подложке), «Фото», «Гость и проживание», «Сообщение гостя», «Тема».
- Факты гостя (`OriginLines`): значок у каждой строки, две колонки, где хватает ширины.
- Карточка «Гостей»: шапка (метки, «Найдено …», что найдено, объект); слева что говорит сигнал,
  справа на своей подложке решение; «Привязать» и «Отклонить» под линией.

### 4. Выключатели источников

- Отзывы: существующий `signal_settings.tasks_enabled` строки `review` через
  `update_signal_settings(p_tasks_enabled, p_kind => 'review')` (только админ).
- Чаты: новая функция админа `set_guest_chats(p_enabled)`: выключение — `messages_enabled` и
  `tasks_enabled` строки `message` в false, очередь и состояние чтения компании очищаются (как
  `docs/one-off-writes/guest-chats-off.sql`); задания cron гасятся, только когда чаты не включены
  ни у одной компании. Включение — как `guest-chats-on.sql`: строка, отметка времени, состояние
  чтения с нуля, задания cron включены.
- Панель: «Настройки → Компания», блок «Задания от гостей», два выключателя; менять — только админ.
  Во вкладке «Гости» «Найдено» и счётчик показывают только виды с включёнными заданиями.

### 5. Reception

Путь «запретов», как сказано владельцем («всё, что менеджер, кроме…»):

- `app_role` + `'reception'` (отдельная миграция: значение перечисления нельзя использовать в той же
  транзакции).
- `is_manager()` — офис: manager, admin, reception. Новая `is_full_manager()` — manager и admin.
- На `is_full_manager()` переходят: доски (политики чтения четырёх таблиц и функции с проверкой
  роли), запись профилей (политика «managers manage profiles» и `guard_profile_privileges` — иначе
  Reception поменяла бы роль себе), `update_signal_settings`, параметры компании в
  `update_host_settings` (видео — раздел «Процесс» — Reception можно).
- Литералы ролей: чаты (`chat_participates*`, `chat_unread_threads`), сообщение гостя
  (`guest_message_target`), журналы уборок (источник «менеджер»), закрытие (`stamp_*_closing`),
  push об отказе и прерывании уборки — Reception как офис. Исполнитель карточки доски и шагов плана —
  по-прежнему manager/admin.
- Edge-функции: `manage-staff` выдаёт роль `reception` (вход — по-прежнему manager/admin),
  `guest-message-text`, `guest-review-text` читают и для Reception; API v1 — значение роли в фильтре
  и в OpenAPI. `_shared/caller.ts` не меняется: ручная синхронизация объектов — не её.
- Панель: доступ `reception` — всё, кроме «Команды»; в «Заданиях» без досок менеджеров; в
  настройках — Аккаунт, Вид, Процесс; во вкладке «Гости» без «Настроек».
- Телефон (OTA): Reception — офис без вкладки «Доски» и без push о карточке. Старые сборки не знают
  роли и показывают экраны горничной — сервер решает, что читать.

## Порядок выката (когда будет слово)

Миграции под заставой → Edge-функции (`manage-staff`, `guest-message-text`, `guest-review-text`,
`api`, `mcp`) → `main` ff-only → OTA preview, затем field.

## Обзоры 19.11

Два независимых обзора (сервер; панель и телефон): CRITICAL нет. Исправлено:

- HIGH: правка описания не доходила до техника — `assign_problem` копирует описание в заметку
  работы. Теперь `edit_problem_text` обновляет заметку живой работы, если её не переписали отдельно.
- HIGH: откат не шёл через `db query -f` (одна команда) — теперь весь откат один блок `do`;
  репетиция гоняет его этим же каналом.
- `_shared/caller.ts` не меняется: через него запускаются и задания сигналов гостей (траты модели —
  рычаг админа). Ручная синхронизация объектов Reception скрыта, ночная идёт как раньше.
- «Команда» проверяет доступ и сама; подтверждение перед выключением чатов и честная подсказка
  (что придёт за время выключения, не прочитается и потом); «Найдено» ждёт выключателей; сетки
  по ширине блока; значок и название роли в «Закрыл» и у людей; блокировка от гонок у выключателя чатов.

## Открытые вопросы владельцу

1. Чаты выключены, а «Показать сообщение из Hostaway» в уже созданном задании из чата по-прежнему
   читает переписку по нажатию. Закрыть и это?
2. Чтение чатов пока идёт только для первой компании (`read-guest-messages` берёт
   `default_host_id`): у другой компании выключатель есть, но читать нечем — для ядра нужен цикл
   по компаниям.
3. Открытый отчёт с категорией, переименованный офисом: если автор потом сам правит его на телефоне,
   заголовок вернётся к названию категории (так работает `update_problem`).
4. Менеджер, ставший Reception, остаётся исполнителем и владельцем своих карточек досок, которых
   больше не видит; это решается переназначением.
5. Reception читает профили сотрудников (телефон, почта) — нужно для назначений; вкладки «Команда» у
   неё нет.
