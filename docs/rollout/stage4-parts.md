## Порядок и слова

Схема всегда раньше панели. Миграции идут по возрастанию времени в имени: CLI откажет, если в облаке есть
миграция новее той, что нужно применить. Если часть пропускается, а потом понадобится, её файлу дают новое
время, и миграцию проверяют заново.

| Слово | Что произойдёт | Условие |
|---|---|---|
| **«выкатывай правку темы»** | Охраняемый `db push` `20261106140000`, затем fast-forward `main` с частью 1 | Голова облака `20261106120000` |
| **«применяй темы комментариев»** | Охраняемый `db push` `20261106150000`. Выключатель остаётся выключенным, панель не меняется | Голова `20261106140000` или ниже, по порядку |
| **«включай темы комментариев»** | `quality-comments-on.sql`: комментарии считаются находками, ночной пересчёт идёт сразу | Только когда кто-то оценил точность словаря на комментариях |
| **«выключай темы комментариев»** | `quality-comments-off.sql`: эпизоды уходят сразу | В любой момент |
| **«применяй схему плана»** | Охраняемый `db push` `20261106160000`. Сотрудники ничего не заметят | По порядку |
| **«выкатывай панель плана»** | Fast-forward `main` с частью 4 | После схемы плана |
| **«выкатывай эффект плана»** | Охраняемый `db push` `20261106170000`, затем fast-forward `main` с частью 5 | После панели плана |

Перед fast-forward ветка сливается с текущей `main`: части сделаны от `424c86e`, и общие файлы
(`coverage.json`, `locales`, `database.types.ts`, `property_quality.sql`) разойдутся. После слияния — полный
прогон.

Застава `db push` как в `docs/rollout/property-quality-1106.md`, шаг 1: `HEAD_WANT`, `LIST_WANT` с ровно одним
файлом, `SHA_WANT`. Окно 03:00–04:40 UTC не задевать. Функции Edge в этом этапе не меняются, деплой не нужен.

Новый `push` не появляется. Запуск плана с ремонтами даёт главному технику по одному `problem_new` на задание,
как и обычные задания: десять ремонтов — десять уведомлений. Приоритет плана ночью срочным не считается.

## Откат

| Часть | Как |
|---|---|
| 1 | `git revert`, затем `problem-theme-hand-rollback.sql` и `migration repair --status reverted 20261106140000 --linked`. Темы, заданные руками, остаются обычными строками |
| 2 | Сначала выключить. `cleaning-comment-themes-rollback.sql` возвращает ночной пересчёт дословно и снимает колонки, затем `migration repair --status reverted 20261106150000 --linked` |
| 3 | Сначала часть 4. `resolution-plans-rollback.sql` откажет, если планы запускались: журнал планов пропал бы. Созданные задания, проверки и заявки остаются обычной работой. Значение `plan` в `problem_source` не удаляется, читатели принимают его за `staff`. Затем `migration repair --status reverted 20261106160000 --linked` |
| 4 | `git revert` слияния в `main`. Запущенные планы живут в базе, их работа — на своих экранах |
| 5 | `git revert`, затем `resolution-plan-effect-rollback.sql` и `migration repair --status reverted 20261106170000 --linked`. Числа запуска остаются в `baseline` |

Запись в облако и `db query --linked` — только по слову. Откаты репетированы на временной базе.

## Связка с themes-v2

Ветка `themes-v2-1106` не выкачена. Её миграция `20261106130000` содержит копию `refresh_property_quality` без
блока комментариев и старше части 2 по времени. Если владелец решит вернуться к v2 после части 2, миграцию v2
надо пересобрать от текущей функции и дать ей новое время. Иначе блок комментариев тихо пропадёт.

## Проверено

Каждая часть — на временной базе поверх головы облака: накат, все наборы, откат. Все части вместе — то же, откат в
обратном порядке оставляет ноль новых функций, таблиц и колонок, ночной пересчёт после него работает. Живой проход
панели на локальном стенде: карточка, «Собрать план», правка, подтверждение, запуск, задание с темой вручную,
закрытие шагов, блок «Что было после плана». Ошибок консоли и сбоев запросов нет, на ширине 390 px ничего не
разъезжается. На настоящих данных панель не открывалась.
