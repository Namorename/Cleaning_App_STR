## Что меняется

**Телефон (горничная, режим каталога):** список категорий сверху вниз — низкая (P4), обычная (P3),
высокая (P2), критическая (P1) в самом низу; внутри уровня — порядок каталога; поиск отвечает в том же
порядке. Подписи «Срочность задаётся категорией» нет, цветная метка осталась.

**Места, где менеджер задаёт срочность нового задания:**

| Место | Было | Стало |
|---|---|---|
| «Новое задание» в панели | 4 уровня (15.11 утром) | без изменений |
| «Новое задание» на телефоне (форма `problem/new`, любая роль) | 4 уровня в форме с вводом названия | без изменений; горничная в режиме каталога срочность не выбирает |
| «Гости»: одобрение предложения из отзыва или чата (`approve_signal_finding`) | 3 уровня, сервер — 3 | 4 уровня; `p_critical`; то, что предложила модель, не меняется — это только начальное значение выбора |
| «Гости»: «Создать задание» вручную (`add_signal_finding`) | выбора срочности в форме нет (обычная) | форма та же; сервер принимает `p_critical` |
| «Качество объектов»: шаги плана решения (`save_resolution_plan` → `launch_resolution_plan`) | 3 уровня | 4 уровня; `resolution_plan_steps.critical`; запуск создаёт задание критическим |
| API v1 `POST /v1/tasks`, MCP `create_task` | `priority=critical` (15.11 утром) | без изменений; новый тест MCP |

Критическая везде хранится как «высокая» + флаг `critical`; старые телефоны видят «высокую».

**Тема задания из каталога** (`20261115150000`): ручной выбор менеджера → тема категории или «не
проблема качества» → находка гостя или словарь, как раньше. У заданий без категории всё как было.
Поле темы в панели: «Определена по категории» / «Не проблема качества». Ночной пересчёт «Качества
объектов» сначала пересчитывает темы заданий из каталога (`refresh_category_themes`), потом всё
остальное как раньше.
