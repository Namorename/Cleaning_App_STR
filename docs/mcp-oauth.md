# Вход в MCP-сервер по OAuth

Решение владельца 09.11: клиенты подключают Claude к woom без ключа. Коннекторы claude.ai, Claude
Desktop и приложения Claude на телефоне подключают удалённый MCP-сервер только по OAuth. Claude Code
тоже умеет входить сам. До этого этапа сервер (`docs/mcp-server.md`) принимал лишь ключ API,
вставленный в настройки помощника.

Ветка `mcp-oauth-1109`. Миграция `20261109120000_mcp_oauth.sql`, функции `oauth` (новая), `mcp` и
`api`, панель: страница согласия и метаданные. Выкат и откат — `docs/rollout/mcp-oauth-1109.md`.

## 1. Как это выглядит для клиента

1. В claude.ai (Customize → Connectors → Add custom connector) вставляют адрес сервера, тот же, что
   для ключа: `https://<проект>.supabase.co/functions/v1/mcp`, и нажимают Connect.
2. Открывается страница woom «Подключение к woom». Если панель не открыта, сначала вход.
3. Админ компании видит, кто просит доступ («Claude») и куда вернётся браузер («claude.ai»). Он
   выбирает название подключения, доступ («Только чтение» или «Оператор», чувствительные права
   добавляются вручную), срок и объекты и нажимает «Разрешить» (или «Отказать»).
4. Claude получает токены и работает. Подключение появляется в Настройки → API с меткой
   «OAuth · Claude», рядом с ключами. Там же можно изменить доступ и отозвать подключение.

Не админ (менеджер) может только отказать. Так же устроены ключи: их создаёт только админ.

## 2. Устройство: подключение — это ключ без собственного секрета

Подключение — строка `api_keys` вида `kind = 'oauth'`, без префикса и без отпечатка. Поэтому для
подключения работает всё, что уже есть у ключа, и ничего не дублируется:

- права: пресет с ручными чувствительными правами, а также объекты;
- срок, лимит запросов, корзина неудачных попыток по IP;
- журнал `api_key_events` и журнал запросов `api_request_log`;
- идемпотентность записи;
- «приостановлен», если создавший админ перестал быть активным админом;
- правка и отзыв в панели (`update_api_key`, `revoke_api_key`).

Секреты подключения — токены, которые выдаёт сервер входа (`oauth_tokens`, только HMAC с
`API_KEY_PEPPER`, как у ключей):

- **access** (`woomat_…`): час, но не дольше срока подключения;
- **refresh** (`woomrt_…`): 90 дней с последнего обновления. При каждом обновлении он тратится и
  выдаётся новая пара (ротация, OAuth 2.1). Повтор в течение минуты получает свою пару: так бывает,
  когда клиент обновляет одновременно из двух мест. Повтор позже значит, что токен скопирован, и
  подключение отзывается с записью в журнале.

Код авторизации (`woomcd_…`) создаёт база и хранит только его sha256. Он живёт 10 минут, работает
один раз и привязан к клиенту, адресу возврата, вызову PKCE (только S256) и ресурсу. Код,
пришедший второй раз, отзывает подключение, сделанное по нему.

Токен OAuth принимает только MCP-сервер: функция `mcp` строит обработчик API с `channel: "mcp"`, и
`api_gate(p_digest, p_ip_hash, p_channel)` ищет токен только для этого канала. REST API зовёт шлюз
по-старому, двумя аргументами, и токен для него не существует (аудитория токена по спецификации
MCP). Старые функции между `db push` и деплоем зовут шлюз двумя аргументами и получают прежний
ответ.

## 3. Кто что делает

| Часть | Где | Что |
|---|---|---|
| Метаданные защищённого ресурса (RFC 9728) | `mcp`, `GET …/functions/v1/mcp/.well-known/oauth-protected-resource` | ресурс = адрес сервера, сервер входа = панель |
| Ответ 401 | `mcp` | `WWW-Authenticate: Bearer realm="woom", [error="invalid_token",] resource_metadata="…"` — единственный путь к метаданным: платформа не отдаёт `/.well-known` в корне проекта, и Claude это поддерживает |
| Метаданные сервера входа (RFC 8414) | панель, `/.well-known/oauth-authorization-server` (открыт без входа) | issuer = адрес панели; `client_id_metadata_document_supported` и метод `none` — по ним Claude выбирает свой документ клиента вместо регистрации |
| Страница согласия | панель, `/oauth/authorize` (за входом) | проверка запроса на сервере, затем выбор доступа и `oauth_authorize` от имени админа |
| Токены, регистрация | функция `oauth`: `/token` (form-urlencoded), `/register` (JSON) | перец есть только здесь |
| Коды, токены, клиенты | база: `oauth_codes`, `oauth_tokens`, `oauth_clients` | клиентским ролям недоступны; панель зовёт `oauth_authorize` и `oauth_client` |

Секретов и настроек Supabase не добавляется. Встроенный OAuth-сервер Supabase не взят: его токен —
полноценная сессия пользователя для PostgREST, и в обход прав ключа клиент получил бы всё, что может
менеджер.

## 4. Клиенты

- **Документ клиента (CIMD), основной путь для Claude.** `client_id` — https-адрес документа:
  `https://claude.ai/oauth/mcp-oauth-client-metadata` (claude.ai, Desktop, телефон, возврат на
  `https://claude.ai/api/mcp/auth_callback`) и `https://claude.ai/oauth/claude-code-client-metadata`
  (Claude Code, возврат на `http://localhost/callback` или `127.0.0.1` с любым портом).
  - Страница читает документ на сервере: без перенаправлений, до 5 секунд, до 16 КиБ. Проверяет,
    что `client_id` в документе тот же, что метод `none` и что адрес возврата объявлен.
  - Если документ Claude не читается, используется копия (`KNOWN_CLIENTS`, снята 09.11). Устаревшая
    копия может только отказать новому адресу, но не пустить чужой.
- **Динамическая регистрация (RFC 7591)**, для остальных клиентов (Cursor, VS Code, Inspector):
  - регистрируются только публичные клиенты;
  - адреса возврата: https, http только на этот компьютер или собственная схема программы, но не
    `javascript:`, `data:`, `file:` и подобные;
  - не больше 5 адресов;
  - 20 регистраций в час с одного адреса и 200 со всех;
  - клиент, не использованный неделю, удаляется.
- Адрес возврата сверяется точно; адрес на этом компьютере (loopback) — с любым портом (RFC 8252).
  Страница показывает хост возврата. Если ответ уходит программе на этом компьютере, страница
  предупреждает.
- Ответ на согласие несёт `iss` (RFC 9207). Пока клиент и адрес возврата не проверены, ошибка
  показывается на странице и никуда не перенаправляет (открытый редирект). После проверки ошибка
  уходит клиенту.
- Страницу согласия нельзя встроить в чужой фрейм (`X-Frame-Options`, `frame-ancestors 'none'`),
  без `Referer`.

## 6. Решения и открытые вопросы

- Новое подключение начинается с «Только чтения» или «Оператора». Полный доступ и свой набор
  делаются правкой в Настройки → API, как для ключа (там же подтверждение названием).
- Отдельный канал MCP в `api_request_log` не заведён: вызовы подключения и так видны по его ключу.
- Отзыв токена отдельной точкой (RFC 7009) не сделан: подключение отзывается в панели, и Claude
  этого не требует.
