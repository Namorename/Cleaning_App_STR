# F10. Веб-панель менеджера — план и чек-лист

Второе приложение с нуля: `apps/web`. Порядок этапов утверждён 2026-09-09.
Каждый этап — отдельный коммит с тестами; выкат по правилу «миграции и
сборка вместе». Чек-лист ведётся здесь: `[x]` ставится, когда этап
закоммичен и проверен в облаке.

## Решения

- **Стек:** Next.js 15 (App Router, TypeScript), Tailwind + shadcn/ui, TanStack
  Query, `@supabase/ssr` (сессия в cookie), i18next с теми же файлами
  переводов, что у приложения уборщицы. Ничего своего не изобретаем.
- **Переводы общие:** `ru/en/cs.json` живут в `packages/shared`, оба
  приложения читают один файл; ключи `serverErrors.*` переводят отказы
  сервера и в панели.
- **Хостинг:** Vercel. В браузер уходят только `NEXT_PUBLIC_*`; секреты
  по-прежнему только в Edge Functions.
- **Доступ:** роль из `app_metadata` (`manager`, `admin`); остальным —
  редирект на вход. Данные защищает RLS, guard в панели — только удобство.
- **Порядок:** сначала то, у чего RPC уже готовы и база не меняется
  (проблемы, заявки) — панель начинает работать быстро и обкатывает каркас
  на малом; задания с миграциями — третьими; команда — раньше объектов,
  потому что без неё уборщицу нельзя завести иначе как SQL.

## Что уже есть на сервере

RLS `for all` у менеджера: `properties`, `tasks`, `reservations`,
`profiles`, `property_cleaners`, `property_links`, `problems`,
`supply_requests`, `supply_request_items`. RPC: `save_workflow_template`,
`save_property_checklist`, `copy_property_checklist`, `waive_task_step`,
`assign_problem`, `cancel_problem`, `resolve_problem`,
`review_supply_request`. Пробел остался один: у `hosts` нет политики записи
(нужна RPC для тумблеров). Пробел по `tasks` закрыт этапом 3 — миграция
`20260910140000_task_title_author.sql` добавила `title`, `title_i18n`,
`created_by` и RPC `save_task`.

Задания — `/tasks`: вкладки «Сегодня / Ближайшие / Завершённые» (просроченное открытое остаётся в «Сегодня», чтобы его было видно), фильтры по исполнителю и типу, поиск; группы по времени суток внутри дня и по дням в остальных вкладках; модалка «Изменить» и она же мастер «Новое задание» (объект, тип, день, окно, исполнитель, заметка и одно необязательное название на языке компании — без названия задание зовётся по типу, полей переводов в форме нет: `20260910150000_task_title_optional.sql`, колонка `title_i18n` осталась и не затирается, если панель её не прислала); drawer «Как прошла уборка» с шагами, фото, проблемами уборки и корректировкой времени (`duration_override_min`, замер не переписывается — §13.3). Схема: `tasks.title` / `title_i18n` / `created_by`, RPC `save_task`; проверка «такое задание на этот день уже есть» живёт в RPC, а не уникальным индексом — занятая квартира вправе получить две уборки в день, поэтому отказ снимается подтверждением (`p_allow_duplicate`), а задания из брони и из проблемы под правило не подпадают. Чтение ограничено окном в 30 дней назад (`HISTORY_DAYS`): вкладка «Завершённые» — недавняя история, а не архив; отчёт за период — F12
- [x] 4. Команда — `/team`: таблица с вкладками «Работают / Отключённые / Все», поиск по имени, почте и телефону, фильтр по роли (счёт на вкладке считается после фильтров, чтобы не спорить со списком под ним). Одна модалка на создание и правку: имя, почта, телефон, роль, язык, «Работает» — тумблер есть только у существующего, нанять отключённым нельзя; почта заводится один раз и в правке заблокирована (перенос логина — операция auth с подтверждением на обе стороны, и поле, которое молча ничего не делает, хуже отсутствующего). Пароль придумывает сервер и показывает ровно один раз: скопировать, отправить новый, дальше он только в хеше. Лист «Объекты» — «Закреплён / Из очереди» и позиция в очереди, каждый контрол пишет на месте через `save_property_cleaner`: у объекта один закреплённый, и отказ называет, кто им уже занят, а не индекс. Схема — `20260911120000_staff_accounts.sql`: `profiles.email` зеркалит `auth.users` триггерами (открыть `auth.users` роли `authenticated` нельзя — там хеши паролей и refresh-токены), `guard_profile_privileges` не даёт клиенту писать себе роль. Учётки заводит Edge Function `manage-staff` (`create` / `update` / `reset_password`) — единственная дверь к Admin API; её отказ панель достаёт из тела ответа (`lib/function-error.ts`), потому что `functions.invoke` отдаёт наружу только «non-2xx». **В облаке ещё нет:** миграция и функция ждут `db:push` и `fn:deploy`, а письма — своего SMTP (встроенная рассылка шлёт только участникам проекта и ограничена парой писем в час; настройки и шаблон Recovery — в `README.md`)
