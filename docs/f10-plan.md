# F10. Веб-панель менеджера — план и чек-лист

Второе приложение с нуля: `apps/web`. Порядок этапов утверждён 2026-09-09.
Каждый этап — отдельный коммит с тестами; выкат по правилу «миграции и
сборка вместе». Чек-лист ведётся здесь: `[x]` ставится, когда этап
закоммичен и проверен в облаке.

## Решения

- **Стек:** Next.js 15 (App Router, TypeScript), Tailwind + shadcn/ui, TanStack
  Query, `@supabase/ssr` (сессия в cookie), i18next с теми же файлами
  переводов, что у приложения уборщицы. Ничего своего не изобретаем.
- **Переводы общие:** `ru/en/cs.json` живут в `packages/shared`, оба
  приложения читают один файл; ключи `serverErrors.*` переводят отказы
  сервера и в панели.
- **Хостинг:** Vercel. В браузер уходят только `NEXT_PUBLIC_*`; секреты
  по-прежнему только в Edge Functions.
- **Доступ:** роль из `app_metadata` (`manager`, `admin`); остальным —
  редирект на вход. Данные защищает RLS, guard в панели — только удобство.
- **Порядок:** сначала то, у чего RPC уже готовы и база не меняется
  (проблемы, заявки) — панель начинает работать быстро и обкатывает каркас
  на малом; задания с миграциями — третьими; команда — раньше объектов,
  потому что без неё уборщицу нельзя завести иначе как SQL.

## Что уже есть на сервере

RLS `for all` у менеджера: `properties`, `tasks`, `reservations`,
`profiles`, `property_cleaners`, `property_links`, `problems`,
`supply_requests`, `supply_request_items`. RPC: `save_workflow_template`,
`save_property_checklist`, `copy_property_checklist`, `waive_task_step`,
`assign_problem`, `cancel_problem`, `resolve_problem`,
`review_supply_request`. Пробелов два: у `hosts` нет политики записи
(нужна RPC для тумблеров), у `tasks` нет `title` и `created_by` для ручных
заданий.
