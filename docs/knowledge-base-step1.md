### Решение владельца 2026-10-31

«Отменим это правило, не удаляй его из базы, но отключи пока. Техники видят всю базу знаний
независимо от заданий.»

- **Правило решения 5 для техника** (объекты текущей работы) не удалено:
  `kb_reader_property_ids()` не тронута. Оно выключено переключателем компании

- **Где в коде:** миграция `20261030103000_kb_techs_read_all.sql`. Она добавляет

  place of the articles they read» на `kb_article_targets`.

`update public.hosts set kb_techs_read_all = false where id = '<host>';`.

## 2. Схема (`supabase/migrations/20261017100000_knowledge_base.sql`)

Новые объекты; существующие таблицы не меняются и строк не получают.

- Перечисления `kb_status` (`draft`, `published`, `archived`) и `kb_scope` (`company`,
  `building`, `properties`).
- **`kb_articles`** — статья: `id` (придумывает панель), `host_id`, `status`, `scope`,
  `language` (язык оригинала), `title` (1–200), `body` (до 20 000, может быть пустым у
  черновика), `rev` (номер версии текста), `rev_stamp` (служебное: какая запись сделала
  текущую версию), `created_by / created_at / updated_by / updated_at`, `published_at`
  (обязателен у опубликованной). Уникальность `(host_id, id)` — на неё ссылаются три другие
  таблицы.
- **`kb_article_targets`** `(article_id, property_id, host_id)` — места статьи со `scope`
  `building` или `properties`. Ключи только составные: `(host_id, article_id)` →
  `kb_articles`, `(host_id, property_id)` → `properties`: статья, место и строка — одной
  компании, и у PostgREST один путь к каждой таблице (без 300).
- **`kb_article_translations`** `(article_id, language, host_id, title, body)` — другие
  языки, каждый по желанию. Отдельная таблица, а не пара `x / x_i18n` из CLAUDE.md: текст
  до 20 000 знаков и версионируется вместе с переводами (решение владельца — «таблицы …
  переводов и версий»).
- **`kb_article_revisions`** `(article_id, rev, host_id, language, title, body,
  translations jsonb, edited_by, created_at)` — текст после каждого сохранённого изменения
  вместе с переводами.

**Версии — работа триггеров**, а не RPC: кто бы ни писал (RPC, сервисный скрипт), правка
текста или перевода делает версию. Одна запись = одна версия, сколько бы строк она ни
тронула: «штамп» записи — номер транзакции и время оператора клиента; статья помнит штамп
записи, сделавшей её текущую версию. Смена мест или статуса версией текста не считается.
Возврат версии — новая версия с тем текстом; история не переписывается.

**Запись** — только три RPC (definer, `search_path = ''`), таблицы клиенту только на
чтение (`revoke all` + `grant select`), матрица — `supabase/tests/table_grants.sql`:

| RPC | Что делает | Отказы (ключ `hint`) |
|---|---|---|
| `save_kb_article(p_id, p_language, p_title, p_body, p_translations, p_scope, p_property_ids, p_expected_updated_at default null)` | создаёт черновиком или переписывает статью, переводы и места; идемпотентна по id панели | `managerOrHeadTechOnly`, `kbArticleInvalid`, `kbTitleRequired`, `kbTitleTooLong`, `kbBodyTooLong`, `translationsInvalid`, `kbTranslationTitleMissing`, `kbTargetsInvalid`, `propertyNotFound`, `kbBuildingInvalid`, `kbArticleNotFound` (id чужой компании), `kbArticleChanged` (экран старше статьи), у опубликованной — `kbBodyRequired`, `kbTargetsMissing` |
| `set_kb_article_status(p_id, p_status)` | публикует, снимает с публикации (в черновик), архивирует, возвращает из архива | `managerOrHeadTechOnly`, `kbArticleNotFound`, при публикации `kbBodyRequired`, `kbTargetsMissing` |
| `restore_kb_revision(p_article_id, p_rev, p_expected_updated_at default null)` | возвращает версию текста новой версией | `managerOrHeadTechOnly`, `kbArticleNotFound`, `kbArticleChanged`, `kbRevisionNotFound`, у опубликованной — `kbBodyRequired` |

Экран называет статью её `updated_at`: его двигает любая запись — текст, перевод, место,
статус, — так что чужая правка мест тоже не будет молча затёрта (находка обзора, M1). Если
хранится ровно то, что присылает тот же автор, это его же запись, повторённая после
потерянного ответа, — отказа нет.
`p_expected_updated_at` — правило CLAUDE.md про новый аргумент: `null` значит «вызывающий ничего
не сказал», проверки нет. Тексты ошибок в базе английские, на экран — по ключу через
`serverErrorText()` (ключи `serverErrors.kb*` в трёх `locales`).

Здание для `scope = building` — объект верхнего уровня, под которым есть комнаты или части;
ровно один. Статья на здании видна в его комнатах и частях.

## 3. Права

| Кто | Читает | Пишет |
|---|---|---|
| менеджер, админ | все статьи своей компании (черновики, архив), места, переводы, версии | да |
| главный техник | то же | да |
| горничная | опубликованные статьи всей компании, объектов, к которым привязана (`property_cleaners`), и объектов, где у неё сейчас есть работа (подмена; объект не в архиве); у каждого такого места — здание над комнатой и комнаты под зданием (как `cleans_property`); их переводы; из мест статьи — только свои | нет |
| техник | с 2026-10-31 — все опубликованные статьи своей компании, их места и переводы. При `hosts.kb_techs_read_all = false` — как до этого: статьи всей компании и объектов, где у него сейчас есть работа (объект в архиве тоже), и здания над ними | нет |
| выключенная учётка, другая компания | ничего | нет |
| без входа (`anon`) | ничего: нет ни одного права на таблицы и функции | нет |

**Работа «сейчас»** — уборка любого вида (`cleaning`, `midstay`, `inspection`,
`maintenance`), назначенная этому человеку, в статусе `assigned / accepted / in_progress /
paused / blocked`. Это открытые статусы списка «мои уборки» телефона (`fetchMyTasks`) без
`unassigned`, у которой исполнителя нет. `done`, `cancelled` и `expired` не считаются.
Горизонт телефона правило не сужает: уборка, назначенная на дальнюю дату, открывает статьи
уже сейчас (как у техника и до правки). Архив
— `properties.status = 'archived'` у объекта самой уборки: архивирование отменяет уборки,
которые ещё не начаты, а начатая, но не закрытая на архивном объекте подмену не открывает.
Здание над таким объектом и комнаты под ним на архив не проверяются — как у привязки.
Для техника архив не проверяется: ремонт на снятом объекте — его обычная работа. Как только
уборку закрыли, отменили или передали другому, место закрывается при следующем чтении.

| Кто (было → стало 2026-10-17) | Читает до | Читает после |
|---|---|---|
| горничная, привязанная к объекту | статьи компании + её объекты (здание ↑, комнаты ↓) | то же |
| горничная на подмене (уборка есть, привязки нет) | только статьи компании | + объект уборки, здание над комнатой, комнаты под зданием; черновики и архив — нет |
| горничная, уборка закрыта / отменена / просрочена | только статьи компании | то же |
| горничная, уборка на архивном объекте | только статьи компании | то же |
| техник | статьи компании + объекты текущей работы и здания над ними | то же |
| главный техник, менеджер, админ | всё своей компании | то же |
| выключенная учётка, другая компания, `anon` | ничего | то же |

Правило — два definer-множества за `= any (array(...))` (строятся раз на оператор, как
`staff_property_ids()`), и это же единственный способ политикам статей и мест спрашивать
друг о друге без рекурсии. Каждая политика держит `host_id = current_host_id()`. Политика
офиса названа так, чтобы стоять в OR первой (`office…` после `field…` по убыванию имён).

Телефон в шаге 1 этих таблиц не читает — правила заложены для шага 2.

## 4. Разметка (`packages/shared/src/knowledge/markup.ts`)

Один разборщик для предпросмотра панели и будущего экрана телефона. Результат — данные
(блоки → строки → куски), которые каждое приложение рисует своими элементами; HTML нет
нигде, `<script>` остаётся текстом.

| Ввод | Что получится |
|---|---|
| пустая строка | конец абзаца; одиночный перенос строки остаётся переносом |
| `**текст**` | жирный (открывается и закрывается на непробеле) |
| `- ` или `* ` в начале строки | маркированный список |
| `1. ` | нумерованный список, счёт от первого номера |
| `1) ` | шаги (крупные номера) |
| `> ` | блок «Важно» |
| `[текст](https://…)` и голый `https://…` | ссылка; только https, без `user:pass@`, с точкой в имени узла, до 2048 знаков (`isSafeHttpsUrl`) |

Разбор однопроходный: тысячи непарных знаков не возвращают читателя к концу строки (тест
на 21 000 знаков). Выбор языка для читателя — `pickKbText`: свой → оригинал (решение владельца
2026-10-17 для телефона, шаг 2; до него между ними стоял английский).

## 5. Панель

- Раздел «База знаний» (`/knowledge`, en Knowledge base, cs Znalostní báze) в группе
  «Справочники»; значок — «заметка» (`sticky-note`): у телефона он уже есть, новый значок
  потребовал бы правки кода телефона.
- **Главный техник входит в панель** — впервые: только «База знаний» и свои настройки
  (аккаунт, оформление); с любой другой страницы proxy отправляет его в `/knowledge`, вход
  ведёт туда же. Остальная панель — по-прежнему менеджеру и админу. Защита данных — RLS, как
  и раньше; proxy — удобство.
- Список: статус (по умолчанию черновики и опубликованные, отдельно черновики,
  опубликованные, архив) и место (все, вся компания, любой объект — с его зданием и
  комнатами); статус, место и открытая статья — в адресе.
- Редактор: язык оригинала, вкладки языков (у пустого перевода пометка «нет перевода»),
  заголовок, текст с кнопками разметки, предупреждение о кодах, «Где показывать», сохранить,
  опубликовать / снять с публикации, в архив / вернуть из архива (правленая статья сначала
  сохраняется), отменить правки, история версий с возвратом (недоступен при несохранённых
  правках), конфликт версий — с кнопкой «Загрузить последнюю версию». Предпросмотр — тот же
  разборщик, ширина телефона 390 pt.
- Места, которых пишущий не видит (главный техник читает только объекты своих заданий),
  сохраняются при его правке и показываются числом.
- Предупреждение о кодах — одна строка на языке панели (2026-10-17).
- **Уход с несохранёнными правками** (2026-10-17, `lib/use-leave-guard.ts`). Пока в форме
  есть что-то, чего нет на сервере (у новой статьи — что-то набрано):
  - ссылка панели (меню, настройки, логотип): вопрос «Есть несохранённые изменения. Уйти и
    потерять их?» на языке панели (`window.confirm`), «Отмена» оставляет экран как был;
  - кнопка «Все статьи»: тот же вопрос;
  - закрытие или перезагрузка вкладки, переход на другой сайт: вопрос браузера своими
    словами — свой текст браузеры там больше не показывают.
  Не спрашивается: ссылка, открытая в новой вкладке (Ctrl, Cmd, Shift, `target`), якорь
  на той же странице, правки уже сохранены. **Не перехватываются:** кнопка браузера
  «Назад» (у App Router нет способа её удержать) и «Выйти» (у неё свой вопрос, после него
  правки теряются).
- Неудачное повторное чтение статьи (фокус окна после потери связи или сессии) больше не
  убирает форму с набранным: экран ошибки — только если статью не удалось прочитать ни разу
  (находка обзора 2026-10-17).

## 7. Выкат — после запуска сотрудников, всё только словом владельца

Шаг 1 не меняет ни телефон, ни медиа, ни существующие таблицы: OTA и сборка не нужны.
Порядок — **сначала схема, потом панель** (`main` = прод-деплой панели; панель ветки зовёт
`kb_*` и без схемы покажет ошибку на `/knowledge`).

### 7.1 Перед push (агент, только чтение)

1. Ветка на origin, гейты зелёные (SQL-наборы, цикл панели, паритет ключей, обзор).
   Короткий предполёт по правилу проекта (сценарий в `.claude/workflows/`) — словом
   владельца.
2. **Голова облака.** `node scripts/cloud-read.mjs docs/rollout/remote_head.sql`. На 17.10 —
   `20261015120000`. Если к выкату появятся новые — имя файла должно оставаться **новее
   головы**; иначе переименовать файл на новую метку времени до push (sha256 файла
   изменится — см. п. 4).
3. **Каталог миграций = облако + один файл.** Две облачные миграции
   `20261010100000_video_from_gallery` и `20261011100000_push_release` живут в
   `phone-1-2-0`, не в `main`. Если к выкату они не влиты — положить их копии
   (неотслеживаемые, не коммитить) и сверить побайтно:

   ```bash
   for f in 20261010100000_video_from_gallery.sql 20261011100000_push_release.sql; do
     [ "$(git show origin/phone-1-2-0:supabase/migrations/$f | sha256sum | cut -c1-64)" = \
       "$(sha256sum supabase/migrations/$f | cut -c1-64)" ] && echo "same $f" || echo "DIFFERENT $f"
   done
   ```

   `npx supabase migration list --linked` — только локальная `20261017100000`, только
   облачных нет. Из дерева без `supabase/.temp/pooler-url` CLI отвечает «IPv6» — скопировать
   файл из корня репозитория.
4. **md5 функций.** Вписаны в шапку `docs/rollout/postpush_knowledge_base.sql` для файла с

### 7.2 Застава и push — словом владельца «пушим»

Из дерева push, одной командой. `db push` под агентом соглашается сам (CLI 2.115 при
`CLAUDECODE`); застава — голова облака и полный список сухого прогона в той же команде,
сбой разбора даёт пустую строку и закрывает заставу. Python на этом компьютере нет — разбор
на node:

```bash
HEAD_WANT=20261015120000
LIST_WANT="20261017100000_knowledge_base.sql"
json() { node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>{try{console.log($1)}catch{console.log('')}})"; }
[ "$(node scripts/cloud-read.mjs docs/rollout/remote_head.sql | json 'JSON.parse(s)[0].head')" = "$HEAD_WANT" ] &&
[ "$(npx supabase db push --linked --skip-vault --dry-run | json 'JSON.parse(s).migrations.join(\" \")')" = "$LIST_WANT" ] &&
npx supabase db push --linked --skip-vault
```

`HEAD_WANT` — голова облака на день выката (п. 7.1.2), не эта цифра вслепую.
