## Что вырезается при записи

Вырезает триггер на обеих raw-таблицах. Функции синка не меняются (md5 те же), передеплоя функций нет.
- **Брони, 40 ключей:**
  - имя, фамилия, e-mail, телефон;
  - адрес, город, индекс, страна;
  - фото, id в канале, прокси-почта;
  - заметки: `guestNote`, `comment`, `hostNote`, пожелания Booking;
  - ссылка и хеш гостевого портала;
  - `customFieldValues`, коды дверей, данные карт (сейчас пустые);
  - имена гостя в каждом `reservationUnit`.
- **Объекты, 20 ключей:** контакт листинга (имя, телефоны, почта, адрес), Wi-Fi логин и пароль,
  `doorSecurityCode`.

**Остаётся, потому что это читает код:**
- у брони — поля нормализации, в том числе `guestName` → `guest_name` → правило «#» служебной брони;
- у объекта — поля нормализации листинга и комнат;
- по плану базы знаний (шаг 6) и F27 — `customFieldValues`, `keyPickup`, `airbnbAccess`, `airbnbNotes`,
  `houseRules` объекта.

**Служебные брони.** Имя на «#» не стирается: `is_service_booking()` отвечает как раньше.

## Риски

- Брони старше 90 дней после выезда в панели показываются без имени гостя: календарь, брони, гость
  выезда на карточке уборки.
- Стирание имени двигает `updated_at`, и клиенты API с `updated_since` увидят такую бронь ещё раз. Имя
  гостя API не отдаёт.
- Поздний вебхук по старой брони вернёт имя до ближайшей ночной очистки.
- Новый личный ключ, который Hostaway добавит позже, хранится, пока его не впишут в список.
