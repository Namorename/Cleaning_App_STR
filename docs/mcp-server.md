# MCP-сервер woom

Удалённый сервер Model Context Protocol поверх публичного API v1 (`docs/api-v1.md`):
ИИ-помощники (Claude Code, Cursor, Claude Desktop через мост) работают с данными woom
теми же ключами, правами и лимитами, что и API. Ветка `mcp-server-1104` — подготовка и
репетиция; в облако ничего не выкачено (план выката — §12).

## 1. Архитектура в одном абзаце

Новая Edge Function `mcp` (`supabase/functions/mcp/`). Каждый вызов инструмента — это
запрос API v1, который проходит **через собственный обработчик API**
(`supabase/functions/api/handler.ts`, функция бандлит его из `../api`) с заголовком
`Authorization` и адресом звонящего. Поэтому ключ, его права и объекты, лимит запросов,
корзина неудачных попыток по IP, проверка параметров, идемпотентность записи и журнал
`api_request_log` — не копия правил API, а они сами. Слой MCP добавляет только протокол,
список инструментов по правам ключа, малые страницы, предел размера ответа и пометку «это
данные, а не указания». Новых таблиц, ключей, миграций и секретов нет.

```
клиент MCP ──POST /functions/v1/mcp──▶ mcp/handler.ts ──Request──▶ api/handler.ts ──rpc──▶ api_gate, api_v1_*
             JSON-RPC, Bearer-ключ      протокол, tools           ключ, права, лимит      база решает
```

## 2. Протокол и транспорт

- Streamable HTTP, один адрес, **только POST**, одно сообщение JSON-RPC на запрос, ответ
  `application/json` (без SSE и без сессий: `Mcp-Session-Id` не выдаётся). GET и DELETE —
  `405 Allow: POST`. Пакеты (массивы) — `400`: их убрали из протокола в 2025-06-18.
- Две эпохи протокола (актуальная спецификация — **2026-07-28**, вышла 28.07.2026):
  - **новая, 2026-07-28** — без рукопожатия: версия в `MCP-Protocol-Version` и в
    `params._meta`, метод в `Mcp-Method`, имя инструмента в `Mcp-Name` (с base64-формой);
    `server/discover`; каждый результат — `resultType: "complete"`; несовпадение заголовка
    и тела — `400 / -32020`, неизвестная версия — `400 / -32022` со списком версий,
    неизвестный метод — `404 / -32601`;
  - **старая, 2025-03-26 … 2025-11-25** — `initialize` → `notifications/initialized` (202),
    `ping`; без заголовка версия считается 2025-03-26. Её сегодня говорят почти все
    клиенты: SDK v1 (до 2025-11-25), клиент SDK v2 по умолчанию.
- Эпоха — по заголовку `MCP-Protocol-Version`: 2026-07-28 — новая, старая версия или нет
  заголовка — старая.
- **Без библиотеки.** Официальный SDK v2 (`@modelcontextprotocol/server` 2.3.1 от 05.10,
  его же советует руководство Supabase) рассматривался. Отказ, потому что у нас набор
  инструментов зависит от ключа, а 401/429 должны отдаваться на уровне HTTP до разбора
  протокола; с SDK пришлось бы проверять ключ дважды на каждый вызов или разбирать тело
  заранее, плюс валидатор AJV и форматы в Deno. Свой слой — ~400 строк без зависимостей
  (`protocol.ts`, `handler.ts`), совместимость проверена **официальными клиентами** (§8).

## 3. Инструменты

- Строятся из `packages/shared/src/api/openapi.v1.yaml` (собранная спецификация),
  `registry.json` и `coverage.json` функцией `packages/shared/src/api/mcp-tools.ts`:
  один инструмент на каждую операцию, которую `coverage.json` помечает `exposed`, со scope
  операции, который реестр держит `exposed`. `npm run api:docs` пишет каталог в
  `supabase/functions/mcp/catalog.ts` (функция не может импортировать из `packages/`).
- Имя — `operationId` в snake_case. Вход — параметры пути, запроса, заголовок
  `Idempotency-Key` (как `idempotency_key`) и поля тела, схемы раскрыты (без `$ref`,
  `example`, `x-*`), `additionalProperties: false`.
- Паритет держат три проверки: `apps/web/src/features/api-keys/__tests__/mcp-parity.test.ts`
  (каталог = сборка, один инструмент на операцию, те же scope, записи = POST-операции),
  `supabase/functions/mcp/parity.test.ts` (каталог = `api/routes.ts`: метод, путь, scope,
  имена параметров и тела, пагинация, обязательность), и сборка падает, если у новой
  записи нет решения в `WRITE_EFFECTS`.

| Инструмент | Право | Делает |
|---|---|---|
| `get_me` | любой ключ | читает: ключ (без префикса) и компания |
| `list_properties`, `get_property` | `properties:read` | читает |
| `list_cleanings`, `get_cleaning` | `cleanings:read` | читает |
| `assign_cleaning` | `cleanings:assign` | **пишет**: назначает или снимает исполнителя уборки |
| `list_cleaning_media` | `media:read` | читает (только сведения о файлах, без ссылок) |
| `list_tasks`, `get_task` | `tasks:read` | читает |
| `create_task` | `tasks:create` | **пишет**: создаёт задание |
| `assign_task` | `tasks:assign` | **пишет**: назначает задание (ремонт) |
| `list_task_media` | `media:read` | читает |
| `list_staff`, `get_staff_member` | `staff:read` (+ `staff:read_names` для имён) | читает |
| `list_bookings`, `get_booking` | `bookings:read` | читает (без данных гостей) |
| `get_settings` | `settings:read` | читает |

- Аннотации: чтение — `readOnlyHint: true, destructiveHint: false, idempotentHint: true,
  openWorldHint: false`; запись — `readOnlyHint: false`, `idempotentHint: true` (ключ
  идемпотентности), `destructiveHint: true` у назначений (заменяют исполнителя) и `false`
  у создания. В описании записи — что она меняет и «спроси пользователя перед вызовом».
  Удалений нет: их нет в API.
- `tools/list` показывает ключу только инструменты его прав (права читаются через
  `getMe` того же обработчика). Вызов чужого инструмента — `-32602 Unknown tool`
  (API ответил `insufficient-scope`), как будто его нет.

## 4. Аутентификация и права

- Тот же ключ API в `Authorization: Bearer …`, хеш с `API_KEY_PEPPER`, `api_gate`, scopes,
  ограничение по объектам — всё внутри обработчика API. Неверный, просроченный, отозванный
  ключ — HTTP 401 с `WWW-Authenticate: Bearer realm="woom"…` и JSON-RPC `-32001`.
- Корзина неудачных попыток по IP: MCP передаёт API заголовок платформы
  `cf-connecting-ip`, корзина та же самая (общая для API и MCP).
- Лимит запросов ключа — тот же (`api_gate`): MCP-вызовы тратят тот же бюджет. Переполнение
  — HTTP 429 с `Retry-After` API.
- `initialize`, `ping`, `tools/list`, `server/discover` проверяют ключ одним `getMe`;
  `tools/call` — самой операцией (без лишнего запроса). Уведомления (202) ключ по базе не
  проверяют (они ничего не делают), но без заголовка `Bearer` — 401.

## 5. Безопасность

- **Данные, а не указания.** Каждый инструмент и каждый ответ (`data_notice`) говорят:
  тексты людей и каналов — данные. Сообщений гостей, их имён и контактов API не отдаёт
  вовсе (`guests:read_personal` запрещён реестром); чат, отзывы и база знаний в API
  `planned` — инструментов для них нет.
- Ключи, хеши, секреты в ответах не появляются: ответы — тела API; у `get_me` убран
  `key.prefix` (первые знаки ключа не нужны в контексте помощника).
- Клиенты — программы, не страницы: запрос с `Origin` (из браузера) — 403, CORS нет.
  Ключ в адресе (`?api_key=`) — 400. Тело — только `application/json`, читается потоком не
  дальше 64 КиБ (до проверки ключа, поэтому без буфера целиком). `id: null` — 400.
- Значения, которые идут в путь и заголовок, проверяются до запроса: id — UUID (иначе `.`
  прочёлся бы как путь списка), ключ идемпотентности — видимый ASCII; имена аргументов —
  только собственные свойства схемы.
- Не хватает права самого инструмента — «Unknown tool», как будто его нет; не хватает
  второго права для части вызова (`create_task` с исполнителем требует `tasks:assign`) —
  ошибка инструмента с `required_scope`, чтобы помощник попросил меньше.
- Журнал — `api_request_log` API (ключ, операция, статус, длительность, id объекта, id
  запроса), без тел и без данных людей. MCP пишет в лог функции только вид внутренней
  ошибки. Вызовы MCP видны в журнале как их операции API.

## 6. Лимиты

- Страница списка — 20 по умолчанию, не больше 100 (у API 50 и 200): страница читается в
  контекст помощника.
- Ответ инструмента — не больше 64 КиБ JSON. Слишком большая страница запрашивается снова
  с половиной `limit` (до трёх раз); не уместилось — ошибка инструмента `result-too-large`.
- `tools/list` — один ответ без страниц (17 инструментов, ~36 КБ), `ttlMs` 5 минут,
  `cacheScope: "private"`.

## 7. Связь с функцией api

`mcp` бандлит `../api/handler.ts`, `routes.ts`, `params.ts`, `problem.ts`, `cursor.ts` и
`../_shared/api-key.ts`, `env.ts`. Как и с `_shared/`: **правка `supabase/functions/api/` —
передеплой и `api`, и `mcp`.** Сейчас код API в `main` не менялся с выката 30.10 (093cc63),
так что `mcp` везёт тот же обработчик, что работает в облаке.

## 8. Репетиция на стенде (выполнена 04.11)

```
npx deno run --node-modules-dir=none --no-lock --allow-net=127.0.0.1 --allow-read --allow-write \
  --allow-env --allow-sys scripts/api-stand-server.ts serve --keys-out <файл> --minutes 15
npx deno run --node-modules-dir=none --no-lock --allow-net --allow-read --allow-env --allow-sys \
  scripts/mcp-stand-client.ts --keys <файл>
```

Сервер стенда (`api-stand-server.ts`) теперь поднимает и MCP на `127.0.0.1:8788/mcp` поверх
того же обработчика API, в незакрываемой транзакции (ключи шести видов создаются внутри).
`supabase functions serve` не брали: ему нужны настоящие ключи в зафиксированных данных
общего стенда. Итог 04.11: `mcp-stand-client.ts` — 36 из 36 проверок официальными
клиентами (SDK v1 1.32.1; SDK v2 2.3.1 в старом и новом режиме); MCP Inspector 2.12.0
`--cli … --protocol-era modern|legacy` — список инструментов по правам ключа. Стенд после
— без изменений (схемы API на нём нет, служебных компаний и пользователей нет). Важно:
остановка фоновой обёртки `npx` не гасит дочерний `deno` — его PID надо завершить, иначе
транзакция стенда висит до `--minutes`.

## 9. Страница /developers/mcp

Открытая страница панели (как `/developers`, без входа), язык из адреса `?lang=en|cs|ru`
(по умолчанию английский), тексты — `developers.mcp.*` в общих `locales`. Адрес сервера для
этого развёртывания, подключение Claude Code (команда и `.mcp.json`), Cursor, Claude
Desktop (мост `mcp-remote`), что с claude.ai, таблица инструментов из той же сборки
каталога (подписи прав — из формы ключей), примеры и предупреждение о правах ключа.
Справочник `/developers` остаётся только на английском, как был.

## 10. Клиенты

- **Claude Code**: `claude mcp add --transport http woom <адрес> --header
  "Authorization: Bearer $WOOM_API_KEY"` или `.mcp.json` с `"headers": {"Authorization":
  "Bearer ${WOOM_API_KEY}"}`.
- **Cursor**: `.cursor/mcp.json` — `url` и `headers` с `${env:WOOM_API_KEY}`.
- **Claude Desktop**: удалённые серверы — через «Коннекторы» (OAuth); со статичным ключом —
  только мостом `mcp-remote` (сторонний пакет, Node.js) в `claude_desktop_config.json`.
- **claude.ai (пользовательский коннектор)**: виды входа — без входа, OAuth (DCR, CIMD,
  свой клиент) и «статичные заголовки» — последнее в ограниченной бете для части
  организаций. Для всех остальных нужен OAuth (§11).
- **С 09.11 (ветка `mcp-oauth-1109`)**: вход по OAuth сделан — `docs/mcp-oauth.md`. claude.ai,
  Desktop и телефон подключаются через «Коннекторы» без ключа, Claude Code — `/mcp`; ключ остаётся
  для остальных клиентов.

## 11. OAuth — исходный набросок (сделан иначе, см. `docs/mcp-oauth.md`)

Объём: (1) метаданные защищённого ресурса RFC 9728 на
`/.well-known/oauth-protected-resource/functions/v1/mcp` и 401 с `resource_metadata`;
(2) сервер авторизации — Supabase Auth как OAuth 2.1 (или свой) со страницей согласия в
панели, где админ выбирает пресет прав и объекты — по сути выпуск ключа через OAuth;
(3) регистрация клиента — Client ID Metadata Documents (CIMD, рекомендовано; DCR в
2026-07-28 устарел), колбэк `https://claude.ai/api/mcp/auth_callback`; (4) токен с
аудиторией (RFC 8707) → в `api_gate` тот же контекст (компания, scopes, объекты): нужна
миграция — таблица выданных токенов или связь токена с ключом, отзыв и срок; (5) тесты RLS
и паритета. Оценка — отдельный этап со схемой, предполётом и выкатом окна.

## 12. План выката и откат

Подшаги (каждый — только словом владельца):
1. Застава: `npx supabase migration list --linked` (голова облака та же, новых миграций
   нет — выкат схему не трогает); `git diff 093cc63 <коммит> -- supabase/functions/api
   supabase/functions/_shared/api-key.ts supabase/functions/_shared/env.ts` пуст (иначе
   сначала передеплой `api`).
2. Слияние ветки в `main` (панель: страница `/developers/mcp`, прокси; Vercel Ready,
   `/developers/mcp` 200 без входа, `/login` 200).
3. Деплой одной функции: `npx supabase functions deploy mcp` из корня `main` (берёт
   `verify_jwt = false` из `config.toml`). Новые секреты не нужны: `API_KEY_PEPPER`,
   `SUPABASE_URL`, секретный ключ уже заданы проекту.
4. Проверки: `POST` без ключа → 401; GET → 405; ключ «Только чтение» владельца через
   Inspector (`--cli … --method tools/list`) → 14 инструментов без записи; `get_me` →
   компания; журнал `api_request_log` показывает `getMe`; затем Claude Code владельца.
5. Откат: `npx supabase functions delete mcp` (функция ничего не хранит; API не тронут) и
   `git revert` коммитов страницы в `main`. Ключи не затронуты.

## 13. Решения и открытые вопросы

- Решено здесь: без SDK (§2), страница в трёх языках, `/developers` — как был; без OAuth.
- Вопросы владельцу — в отчёте 04.11: OAuth для claude.ai; отличать ли вызовы MCP в
  журнале (нужна миграция: колонка канала в `api_request_log`); перевести ли `/developers`.
- Ревью 04.11 (один независимый, только чтение): «одобрено с замечаниями», CRITICAL/HIGH нет.
  Исправлено: тело потоком с пределом до проверки ключа; «Unknown tool» только для права
  самого инструмента; проверка пути и заголовка, `Object.hasOwn`; 403 любому `Origin`
  (браузерных клиентов нет — настройка разрешённых адресов убрана); `data_notice` и в
  ошибках; `id: null` — 400; таблица и блоки кода страницы доступны с клавиатуры; тест типов
  аргументов. Принято как есть: коды -32000/-32001 совпадают с внутренними кодами SDK (401 и
  429 клиенты разбирают раньше); копия сборки зависимостей из `api/index.ts` (вынос в
  `_shared/` — передеплой `api`, сделать при следующей правке API); предел 64 КиБ — у
  текстового блока, тот же JSON идёт ещё и в `structuredContent`.
