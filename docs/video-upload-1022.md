# Видео не загружается: разбор 22.10

Жалобы горничных с понедельника 19.10: «видео не загружается, хотя оно короткое».

Разбор сделан 22.10, только чтением:
- облако — через `scripts/cloud-read.mjs`;
- Sentry — токеном для чтения;
- код телефона — ветка `phone-1-2-0` (e820308). Этот код и стоит на телефонах:
  - iPhone 1.2.0 (3), канал field, обновление `01a145f3`;
  - Android, канал preview, обновление `01a145dd`.

Журналы хранилища и API Supabase не прочитаны — см. «Что не проверено».

Повторить счёт: `node scripts/cloud-read.mjs docs/rollout/video_upload_probe.sql`.

## Главное

1. **Всё, что телефон успел зарегистрировать, дошло.**
   - С 19.10 — 60 видео: 21 с камеры, 39 из галереи. У всех есть файл в хранилище.
   - Нет строк «ждёт файл», файлов без строки и расхождений размера.
   - Значит, видео теряется **на телефоне, до регистрации** — там, где сервер ничего не видит.
2. **Доказанная причина № 1 — разрешение на фото на iPhone.**
   - Перед открытием галереи приложение спрашивало доступ к фото. Если горничная однажды
     нажала «Не разрешать», галерея больше не открывалась: второй раз телефон не спрашивает.
   - Системному выбору файла (PHPicker на iPhone, Photo Picker на Android) это разрешение
     не нужно вовсе — проверка была лишней.
   - Sentry: `MediaLibraryDeniedError` — 58 событий, только на двух iPhone:
     - iPhone 15 Pro Max, iOS 18.7.8 — 34 события;
     - iPhone 16 Pro Max, iOS 26.6.2 — 24 события.
   - Время событий совпадает с открытием видео-шага до минуты.
   - **Первый iPhone — `b2220edc`.**
     - Ошибки 19.10 в 06:59–07:00 и 12:17–12:22 UTC.
     - Сразу после них она сняла камерой приложения ролики по 2–3 с (07:01, 12:31, 12:32) —
       это и есть «очень короткие видео».
     - С 20.10 ошибок нет, её видео из галереи идут.
   - **Второй iPhone — `12b1defa`.**
     - Ошибки 21.10 в 18:46 и 22.10 в 05:34, 07:37, 13:07–13:10.
     - У неё ни одного видео и ни одного фото.
     - 5 уборок стоят на обязательном видео-шаге, 1 уже истекла.
3. **Вероятная причина № 2 — предел 50 МБ на телефоне для видео из галереи.**
   - Телефон сам отказывает в файле больше 50 МБ (`STORAGE_FILE_LIMIT_MB = 50`, поставлено
     10.10 под Supabase Free).
   - При этом проект на Pro с 16.10, бакет принимает 150 МиБ, в компании стоит 140 МБ.
     Телефон всё равно режет на 50.
   - Такой отказ видит только горничная: в Sentry он не уходил.
   - Битрейт дошедших видео из галереи — от 0,8 до 16,1 Мбит/с. Самое большое — 45,2 МБ;
     между 45 и 50 МБ нет ни одного.
   - Сколько секунд влезает в 50 МБ:

     | Видео | Битрейт | Влезает |
     |---|---|---|
     | Самый высокий дошедший | 16 Мбит/с | 25 с |
     | Оригинал iPhone 1080p | 10 Мбит/с | 40 с |
     | Оригинал Android 1080p | около 17 Мбит/с | 24 с |
     | Оригинал 4K | — | около 8 с |

   - На Android сжатия при выборе нет вовсе. Все дошедшие с Android видео из галереи —
     низкого битрейта (1,2–7,3 Мбит/с), то есть их уже сжало что-то другое.
   - Прямого доказательства (события отказа) нет: до этой ветки такие отказы никуда не
     отправлялись. Ветка начинает их отправлять.
4. **Видео с камеры приложения работают.**
   - 21 видео, 1,7–2,8 Мбит/с, длиной до 103 с.
   - Ни одной ошибки записи в Sentry.

## Что исключено

- **Миграция галереи не накачена** — накачена, 39 видео из галереи дошли.
- **Бакет не принимает тип файла** — принимает `video/mp4` и `video/quicktime` до 150 МиБ.
  Все дошедшие видео — mp4 или mov.
- **Политика хранилища** — запись одна: «строка ждёт файл от своего автора». Строк без
  файла нет ни одной.
- **Битый файл, разный размер** — расхождений строки и объекта 0.
- **Секунды против миллисекунд, адрес загрузки TUS** — по коду всё верно, загрузки идут.

## Что не проверено

    классификатор агента отклонил как работу с учётными данными.
  - Владелец может посмотреть сам:
    - Dashboard → Logs → Storage и API за 19–22.10, фильтр `upload/resumable` и

  будет в Sentry.

(нативный модуль) — отдельная задача и новая сборка, не здесь.

### Глобальный предел проекта (слово владельца)

- Сейчас он неизвестен (см. «Что не проверено»). На Free был 50 МБ, на Pro его можно поднять.
- Нужно 150 МиБ = 157 286 400 байт — как у бакета.
- **Через Dashboard:** Storage → Settings → Upload file size limit → 150 MB → Save.
  Откат — вернуть прежнее значение; записать его до правки.
- **Через Management API** — в окне владельца:
  - токен CLI — в `SUPABASE_ACCESS_TOKEN`;
  - `<ref>` — из `supabase/.temp/project-ref`.

```
# 1. прочитать и записать текущее значение
curl -s -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" https://api.supabase.com/v1/projects/<ref>/config/storage
# 2. поднять до 150 МиБ
curl -s -X PATCH -H "Authorization: Bearer $SUPABASE_ACCESS_TOKEN" -H "Content-Type: application/json" -d '{"fileSizeLimit":157286400}' https://api.supabase.com/v1/projects/<ref>/config/storage
# откат: тот же PATCH со значением из шага 1 (на Free было 52428800)
```

### Порядок выката

1. **Глобальный предел.** Владелец поднимает его или решает не трогать. Во втором случае
   третий коммит снимается: `git revert <sha>` на ветке.
2. **Проверки перед `eas update`** — обычные:
   - `migration list --linked`;
   - натив против коммита последнего бандла (в ветке только JS).
3. **OTA на preview (Android)**, проверка на одном телефоне:
   - на iPhone с запрещённым доступом к фото кнопка «Выбрать видео из галереи» открывает
     галерею;
   - видео на 60–100 МБ уходит.
4. **`update:republish` на field** (iPhone).
5. **Через 1–3 дня** — `video_upload_probe.sql` и Sentry:
   - сколько уборок осталось без видео;
   - новые issues «Gallery video refused» и «Media upload gave up» с причинами.

## Временное обходное средство (до обновления)

- **iPhone с «Доступ к галерее не разрешён»:** Настройки → woom → Фото → «Полный доступ».
  Так было у первого iPhone: после 19.10 ошибки прекратились, её видео из галереи идут.
- **Снимать кнопкой «Записать видео» в самом приложении, а не камерой телефона.**
  - Все 21 видео с камеры приложения дошли. Камера сама держит размер и длину.
  - С 22.10 14:47 в настройках компании 4500 кбит/с. Камера пишет около 4,7 Мбит/с и при
    пределе телефона 50 МБ сама останавливается примерно на 85 с — раньше 120 с шага.
  - До обновления лучше вернуть 2000–2500 кбит/с: при 2 Мбит/с 120 с — это около 30 МБ.
- **Если нужно из галереи:**
  - видео не длиннее 25 с, если оно снято в 4K или в высоком качестве;
  - или снимать телефоном в 1080p, 30 к/с (iPhone: Настройки → Камера → Видеозапись →
    1080p HD, 30 к/с) — тогда до 40 с.
  - Это расчёт от предела 50 МБ по битрейтам дошедших видео, а не наблюдённые отказы.
