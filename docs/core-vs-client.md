# Ядро и клиент

Правило владельца от 14.11.2026. Отсюда оно попадает в `CLAUDE.md` и действует для каждого
изменения.

## Пометка запроса

Каждый запрос владельца помечен одной из двух меток:

- **CORE** — ядро продукта. Его показывают другим клиентам.
- **CLIENT:<имя>** — делается под одного клиента. Сейчас клиент один: **Wagner Stays**
  (`CLIENT:Wagnerstays`). В облаке это единственная компания `ce77c272-c330-4b74-ac98-c7d36cba8b2a`
  («Primary host»).

Если пометки нет, перед работой задаётся **один короткий вопрос**: ядро это или клиент.

## Как делается клиентское изменение

- **Настройкой или данными, не кодом.** Клиентское поведение включается одним из трёх способов:
  - колонкой-настройкой компании (`hosts.*`);
  - каталогом или таблицей с данными компании;
  - флагом.
- **Отдельной ветки кода под клиента нет.** Имя клиента в коде не пишется, нет условий вида
  «если это Wagner».
- **Ядро работает без клиентского.** Новая настройка по умолчанию даёт поведение, которое было до
  неё, у каждой компании. Новая колонка или таблица пуста или выключена, пока её не включили для
  конкретной компании.
- **Данные клиента грузятся отдельно от миграции ядра.** Их заливает одноразовый скрипт в
  `docs/one-off-writes/` с откатом рядом. Миграция ядра создаёт только место под данные: таблицу,
  колонку, настройку. Скрипт с данными клиента помечается `CLIENT:<имя>` в первой строке.
- **Код ядра может появиться из-за клиента.** Тогда это код ядра: у него те же тесты, тот же
  паритет API и то же поведение «по умолчанию как было».

## Как узнать, что правило выполнено

- В миграции нет имени и id клиента.
- Тест показывает, что компания без настройки ведёт себя как раньше.
- Включение и выключение для клиента — запись данных со скриптом отката, а не выкат кода.
- В отчёте сказано, что ядро и что клиент.

## Пример: каталог категорий заданий (14.11.2026)

Запрос помечен `CLIENT:Wagnerstays`. Подробности — `docs/problem-categories.md`.

| Часть | Что это | Где |
|---|---|---|
| таблица `problem_categories`, колонка `problems.category_id`, настройка `hosts.problem_report_mode` | ядро: место для каталога, по умолчанию `free_text` | `supabase/migrations/20261115100000_problem_categories.sql` |
| `report_problem` и `update_problem` с `p_category_id` | ядро: срочность по категории ставит сервер; без категории — как раньше | та же миграция |
| поле категории с поиском на телефоне | ядро: показывается горничной компании с режимом `catalog` | `apps/mobile/src/features/problems/` |
| 27 категорий Wagner Stays с переводами и синонимами | клиент: данные | `docs/one-off-writes/wagner-problem-categories.sql` |
| `problem_report_mode = 'catalog'` для Wagner Stays | клиент: настройка | `docs/one-off-writes/wagner-problem-report-mode-catalog.sql` |
