# Заметки разработчика

Практические ловушки и рецепты, найденные в работе над STR Ops (август —
октябрь 2026). Правила проекта — в `CLAUDE.md`, здесь их нет; здесь то, что
экономит час при повторной встрече: окружение Windows, Claude Code и ECC,
тесты, база, телефон, панель, ветки, стенды. Установка нового компьютера —
`docs/new-machine-setup.md`.

Формат: что происходит → как с этим работать. Дата — когда найдено.

## Windows и оболочка

- **Python пишет CRLF и падает на кириллице.** `write_text` без `newline='\n'`
  даёт CRLF, `print` кириллицы — `UnicodeEncodeError` (консоль cp1251). Скрипт —
  файлом и `python -X utf8 file.py`, запись — `newline='\n'` или байтами.
  `print`/`sys.stdout.write` в конвейер тоже дают CRLF: тело функции, перенакатанное
  через `python … > file.sql` → `psql`, легло в `prosrc` с CR, и md5 разошёлся с
  тем, что везёт `db push` (27.09). Перенакат тел — только файлом.
- **Переводы строк проверять `git ls-files --eol <файл>`** (`i/lf w/lf`), а не
  `grep -c $'\r'`: в Git Bash тот насчитывает CR в чистом LF-файле.
  `.gitattributes` держит `eol=lf` для всего текста.
- **Heredoc с одинарными кавычками внутри роняет bash** («unexpected EOF») даже при
  `<<'EOF'`. Большие скрипты — файлом.
- **Юникод-эскейп во вводе инструмента может прийти готовым символом.** Набранный
  в команде или тексте ` ` иногда доходит до программы голым NBSP, иногда
  буквально — непостоянно (26.09). Буквальный слэш строить в коде:
  `String.fromCharCode(92)` в node, `chr(92)` в SQL, в SQL-пробах сразу `chr(160)`.
  После записи сверять байты: `grep -c $'\xc2\xa0' файл` (ожидается 0).
- **PowerShell 5.1: `>` пишет UTF-16** — grep его не читает. Писать
  `| Out-File -Encoding utf8 <файл>`.
- **curl из Git Bash портит кириллицу в `-d` JSON** (`PGRST102`). Вызовы RPC с
  русским текстом — node-скриптом через `fetch`.
- **Порты.** 8081 бывает занят чужим процессом — веб телефона на 8090. Порт 3100
  после перезагрузки попадал в зарезервированный диапазон Windows (`listen
  EACCES`) — брать 8096 и `-H 127.0.0.1`. Остановить сервер: `netstat -ano | grep
  :<порт>`, затем `taskkill //PID <pid> //F //T`.
- **Перенос дерева ломает ссылки пакетов.** npm кладёт
  `node_modules/@str-ops/{mobile,shared,web}` как junction с абсолютным путём;
  после `git worktree move` они смотрят в старое место, и jest видит `undefined`
  вместо экспорта, а не «module not found» (03.10). Пересоздать:
  `cmd /c rmdir <ссылка>` и `cmd /c mklink /J <ссылка> <новый путь>` — или
  `npm ci` в новом дереве (~5 мин).
- **Удалять временное дерево — из основного checkout**, не изнутри: Windows
  держит папку открытой.

## Claude Code и ECC

- **GateGuard отклоняет первую запись каждого файла** (и первый Bash в сессии),
  даже если факты уже в тексте; повтор того же вызова проходит. Новый файл —
  абзац фактов и два одинаковых Write в одном сообщении; правка — Edit, при
  отказе тот же Edit следующим ходом (второй Edit в том же сообщении не найдёт
  `old_string`). `ECC_GATEGUARD=off` — решение владельца.
- **Сессия внутри worktree отклоняет то, что не может разобрать:**
  `git -C <другое дерево>`, `python - <<'EOF'`, программы `awk` и `sed -n '/…/p'`.
  Проходят простые `cp`, `grep`, `git add/commit` в своём дереве. Правки — Edit
  и Write, сообщение коммита — по-английски, файлом и `git commit -F`, разбор JSON — `python -c`
  одной строкой. `supabase/.temp` (для `--linked`) копируется в дерево из
  основного.
- **`cd` в Bash сдвигает рабочий каталог сессии**, а `/ultrareview` пакует ветку
  этого каталога — к концу хода возвращать его на место.
- **Агенты и память.** На старом компьютере (16 ГБ) — не больше двух агентов
  одновременно на все линии вместе (слово владельца 03.10); тяжёлые прогоны
  (jest, vitest, tsc, next build, deno, `test:rls`) — по очереди через замок
  `testlock.mjs` (бандл переезда, `scratchpad-tools/`). Сценарии воркфлоу
  ограничивают агентов сами: `limited()` с `MAX_AGENTS`, образец —
  `.claude/workflows/f11-preflight.js`. 25.09 сессия упала по памяти при трёх
  агентах. Перед тяжёлым прогоном — закрыть браузеры, лишние контейнеры стека
  выключить.
- **Схема в агенте воркфлоу — только для коротких полей.** Синтезатор, которому
  велели вернуть 25 КБ SQL полем JSON, пять раз не собрал валидный ответ и
  уронил прогон. Код — без схемы, markdown с огороженными блоками. Упавший
  прогон чинится правкой сценария и `Workflow({scriptPath, resumeFromRunId})` —
  готовые агенты вернутся из кэша.
- **Агент воркфлоу может зависнуть после Bash** без процесса и без результата.
  25–30 минут тишины в `agent-<id>.jsonl` → `TaskStop` и возобновление. Долгий
  node не направлять в `| head`, у `curl` — `--max-time`. `scriptPath`
  отклоняется после смены рабочего каталога — копия сценария в текущий каталог.
- **Вердикт скептиков зависит от установки, а не от истины.** «Считай неверной,
  пока не доказано» опровергает всё (13 из 13, четыре были верны); «выясни,
  правда ли» оставляет всё и размножает одну проблему по линзам (31 находка →
  9 различных). Перед отчётом схлопнуть по `file:line` и механизму, каждую
  CRITICAL/HIGH проверить самому — по коду, а утверждение о данных — запросом.
- **Независимый обзор:** новые агенты `ecc:code-reviewer` (не fork — он несёт
  контекст сессии), только дифф и код; без `docs/`, журналов предполётов,
  сообщений коммитов и `git show`; фокус — то, что не чинится по воздуху;
  части по смыслу. Находки CRITICAL/HIGH перепроверить опытом, чинить тестом
  сначала.
- **Классификатор разрешений** блокирует `vercel env add/rm` и `vercel
  deploy/redeploy` — подготовить команду и отдать владельцу через `! …`. В режиме
  `claude -p` всё из `ask` (в т. ч. `git push`) отклоняется; три отказа
  классификатора подряд или 20 за сессию обрывают прогон; «no verdict» — пережидать
  чтением, не повторять.
- **`eas-cli` без терминала** сам уходит в non-interactive и падает на первом
  вопросе («stdin is not readable»). Команды с меню и входом (`eas login`,
  `eas credentials`, первая `eas build -p ios`, `eas submit`) — в окне
  владельца; через `!` — только полностью заданные флагами (`eas update --branch
  …`, `eas env:set …`).
- **MCP `chrome-devtools`** подключается нестабильно — живые прогоны через
  puppeteer (раздел «Стенды»).
- **`/ultrareview`** — лимит 500 файлов и 8 000 строк диффа, через Remote Control
  недоступен, бесплатные запуски кончились 30.09. Снимок для большого диффа:
  база = дерево `git merge-base main <ветка>` + из ветки только документы, тесты
  и типы; снимок = дерево ветки байт в байт поверх базы (`commit-tree`);
  `/ultrareview <sha базы>`. Базу от текущего `main` не брать: если он ушёл
  вперёд, обзор увидит «откат» чужих правок.
- **Ночной запуск без присмотра (25.09) не сделал ни шага:** драйвер Wi-Fi
  отключил адаптер при погасшем экране. Только кабель (или без энергосбережения
  адаптера), ожидание сети дольше. Страховочный `CronCreate` срабатывает, только
  когда REPL простаивает. Режим «всегда включён» — `docs/new-machine-setup.md`, §2.

## Тесты

- **Jest — только из `apps/mobile`** (`cd apps/mobile && npx jest src/...`); из
  корня с `--rootDir` все наборы дают «0 tests».
- **RNTL здесь асинхронный:** `await render(...)`, `await fireEvent.press(...)`;
  без `await` — «overlapping act() calls», и следующие тесты файла читают
  устаревшее дерево. Фабрика `jest.mock` ссылается только на переменные с
  префиксом `mock`. `screen.unmount()` посреди теста ломает рендеры следующих —
  два элемента рисовать одним `render`. `UNSAFE_getByType` в RNTL 14 нет: модуль
  компонента мокать с записью props. `onTestFinished` — только в vitest; в jest —
  `afterEach(jest.restoreAllMocks)`, иначе шпион `Alert` течёт в следующий тест.
- **Новый маршрут Expo Router не проходит `tsc`,** пока dev-сервер не
  перегенерирует `.expo/types/router.d.ts` — перезапустить `expo start`.
- **`npx expo lint` ставит `eslint-config-expo` и создаёт
  `apps/mobile/eslint.config.js`** — откатывать, если линт не входит в задачу.
- **vitest панели под нагрузкой:** два теста упираются в 5 с (`calendar-view`,
  `dashboard-view`). Проверочный прогон — `--maxWorkers=2 --testTimeout=15000`;
  упавший по таймауту файл — отдельно с `--reporter=verbose`, прежде чем звать
  это поломкой.
- **`deno check` точки входа Edge Function** из корня падает на npm-пакетах
  корневого `package.json`. Рабочий способ: `npx -y deno@2 check
  --node-modules-dir=none supabase/functions/<fn>/index.ts` (первый раз ~5 мин,
  фоном), затем `git checkout -- deno.lock` (он дописывает ~10 тыс. строк).
  `deno test` проверяет типы тестов, но не `index.ts`. `deno fmt` в проекте не
  принят; `deno lint` на `send-push` даёт 5 старых `no-import-prefix`.
- **Prettier без конфига.** Конфига нет, стиль держится руками и eslint'ом;
  голый `npx prettier --write` превращает файл в дифф на сотни строк. Только
  `npx prettier --single-quote --print-width 100 --trailing-comma all --write
  <файлы>` и затем смотреть сам `git diff`: посторонние хунки откатывать.
- **SQL-наборы идут одной транзакцией** — `now()` у всех строк один: новое
  сообщение никогда не «новее» маркера прочтения. Время задавать руками как
  `postgres` (`update … set last_read_at = last_read_at - interval '1 hour'`).
- **Локальный стек общий для всех агентов.** Агент, которому велели «проверь
  через psql», создаёт фикстуры и пересоздаёт объекты схемы (в предполёте
  вернулась удалённая миграцией функция с правами по умолчанию). Мерить в одной
  откатываемой транзакции (`begin` → `set local session_replication_role =
  replica` → загрузка → подсчёты → `rollback`); перед замером сверять тела
  функций с файлом миграции (`select prosrc from pg_proc …`).

## База и Supabase CLI

- **`npx supabase db query -f` берёт ровно один оператор** и отдаёт результат
  только последнего; многострочный SQL — только через `-f`. Проверки выката —
  одним `select … union all …`. Вывод JSON содержит `boundary`/`warning`.
- **Проверка под каждым человеком в одном SELECT:** `cross join lateral (select
  set_config('request.jwt.claims', …, true) as c) cfg` и вызов в подзапросе с
  `where cfg.c is not null`. Ссылка на `cfg.c` только в списке выборки связь не
  держит — вызов уходит в InitPlan и считается один раз (образец —
  `docs/rollout/window3_rule_check.sql`).
- **`lock table` в миграции — только внутри `do $$ … $$`:** CLI шлёт файл одной
  конвейерной транзакцией, и на верхнем уровне он отвергается.
- **`security definer` SQL-функция не инлайнится** и планируется обобщённым
  планом: `($1 is null) or col = any($1)` даёт Seq Scan, хотя литеральный запрос
  в psql показывает индекс. Мерить только вызовом самой функции
  (`auto_explain.log_nested_statements` под `supabase_admin` или `prepare` +
  `plan_cache_mode = force_generic_plan`). Ветки по параметрам — `union all` с
  одноразовым фильтром; CTE, упомянутую дважды, — `not materialized`. Вложенный
  definer-вызов из функции, которую генератор зовёт построчно, сделал его
  вчетверо медленнее — горячий путь держать двумя копиями и тестом паритета. В
  триггере уровня оператора константы-функции вычислять один раз в `declare`.
- **Пермиссивные политики RLS складываются в `OR` по убыванию имён.** Дорогая
  политика с подзапросом, названная «раньше» `is_manager()`, заставляет
  менеджера платить подзапрос на каждой строке (×2–3 буферов на чате). Называть
  дорогие так, чтобы шли после дешёвых, и закреплять порядок проверкой `Filter`
  в `explain (costs off)` под `authenticated`. Общий для всех веток конъюнкт
  (`host_id = current_host_id()`) Postgres выносит в индексное условие — не
  удалять его «как дубль» из одной политики.
- **401 `PGRST303` «JWT issued at future»** — не «anon до сессии», а часы
  PostgREST до 14.18 после простоя (облако — 14.5). Свежий токен иногда
  считается выданным в будущем. Панель повторяет такой отказ сама
  (`stale-clock-retry.ts`), телефон — повторами TanStack. Окончательно лечит
  апгрейд проекта (снимок «до» и порядок проверки — бандл переезда,
  `postgrest-upgrade-2026-10-02/RUN.md`).
- **Схема `raw` в облаке в PostgREST не выставлена** — читается только SQL.
- **Галерея** (`gallery_allowed`) включается только после того, как сборка,
  объявляющая источник медиа, есть у всех: сервер отбивает медиа без
  источника, и старая сборка в поле получит отказ.

## Телефон (Expo)

- **`expo config --type introspect` видит только манифест приложения;**
  манифесты библиотек сливает Gradle при сборке. Перед словами «новое
  разрешение» — читать `android/src/main/AndroidManifest.xml` каждой нативной
  зависимости. Модуль с `android.publication` ставится готовой библиотекой, и
  его Gradle-флаги не действуют (только `expo.autolinking.android.buildFromSource`).
  Плагин с опцией `false` может писать в `Info.plist` (expo-video: пустой
  `UIBackgroundModes`) — сверять introspect до и после по разделам.
- **`locales` верхнего уровня в конфиге Expo уходит на обе платформы:** тексты
  разрешений iOS класть под `locales.<язык>.ios`, иначе Android падает на
  `:app:lintVitalRelease` (ExtraTranslation) — первая сборка 1.1.0 (02.10).
  Сторож — `app-config.test.ts`.
- **Коммит последнего OTA хранит EAS, не репозиторий:** `npx eas-cli update:list
  --all --json --non-interactive --limit 5` (stdout — JSON, stderr — копия для
  человека: писать раздельно), затем `npx eas-cli update:view <group> --json` →
  `gitCommitHash`. Установленная сборка — `build:list`; внешний импорт сверять с
  `package.json` коммита сборки. `eas update` идёт ~12 мин — фоном.
- **Лог падения на Android:** `adb logcat -b all -c`, воспроизвести, `adb logcat -d
  -v threadtime | Out-File -Encoding utf8 crash-log.txt`. Фильтр по pid бесполезен
  (процесс умирает). `E ReactNativeJS` + `ErrorRecovery` — ошибка JS (чинится
  OTA); `Fatal signal` — нативная. Сначала лог, потом гипотезы.

## Панель (Next.js, Vercel)

- **`Link href="#id"` прокручивает только при первом щелчке;** простой
  `<a href="#id">` ломает «Назад» (запись истории без `state`). Якорь внутри
  страницы — `Link` плюс `onClick={() => document.getElementById(id)?.scrollIntoView()}`.
- **Правка `locales/*.json` при запущенном `next dev`** даёт hydration mismatch
  (сервер отдаёт ключ, клиент — перевод) — перезапустить dev-сервер.
- **Vercel:** коммит `main`, не трогающий панель, Vercel отменяет сам —
  `CANCELED` не сбой. Пересборка — `npx vercel redeploy <url git-деплоя>`;
  `vercel --prod` из `apps/web` грузит всё монорепо и висит. Состояние деплоя —
  MCP `list_deployments` с полным sha или `target=production` (по короткому sha
  пусто); `vercel inspect | grep` в цикле не работает — формат не совпадает.
  Хвост лога сборки `npm error …` ничего не говорит — нужна часть после
  «Creating an optimized production build».

## Ветки и документы

- **Стопка веток, которые входят в `main` по отдельности:** правка файлов нижней
  ветки (миграции, функции, SQL-тесты), сделанная на верхней, коммитится и в
  нижнюю (`git worktree add` нижней, `git checkout <коммит> -- supabase/…`,
  коммит, слияние нижней обратно в верхнюю — дерево не меняется). Иначе `main`
  получит старый SQL, а облако — новый. Перед push в `main`, пока стопка открыта:
  `git merge-tree --write-tree --name-only main <ветка>` — путь, добавленный
  обеими сторонами, это add/add-конфликт.
- **Ссылки на строки ROADMAP.** `docs/redesign-plan.md` (и ранбук F11) ссылаются
  на номера строк; вставка строк сдвигает все ссылки ниже. После правки:
  `git diff -U0 docs/ROADMAP.md | grep ^@@`, пересчитать по ханкам; голые `:NNN`
  искать отдельно. Правка в той же строке ссылок не двигает — предпочитать её.

## Стенды и живые прогоны

- **Стенд панели против локального стека** (календарь, дашборд): `apps/web/.env.local`
  смотрит в облако, а переменные окружения важнее файла — и сборка, и
  `next start` с ключами стека: `NEXT_PUBLIC_SUPABASE_URL=<API_URL>
  NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<PUBLISHABLE_KEY> npx next build
  --no-mangling` (значения — `npx supabase status -o env`), затем `npx next start
  -p 8096 -H 127.0.0.1` (`CALENDAR_FIXTURE=1` для календаря). Менеджер стенда —
  admin API локального Auth (`app_metadata.role = manager`) и
  `update public.profiles set role = 'manager'` (триггер ставит `cleaner`);
  `db:reset` стирает его. Скрипт и данные — бандл переезда
  (`scratchpad-tools/stand-manager.mjs`, `stand-dashboard.sql`); пароль — только в
  файле рядом. Комната в сиде: `id = property_id_for_unit(unit)`.
- **Драйвер** — `puppeteer-core@24`, установленный в скретчпаде (`npm init -y &&
  npm i puppeteer-core@24`), не в репозитории; Chrome из Program Files.
  `protocolTimeout: 600_000` под замедлением CPU ×4 и новый
  `browser.createBrowserContext()` на каждый прогон (иначе второй уже вошёл и
  `/login` уводит на дашборд). Числа сравнимы только «до/после» одного вечера;
  перед прогоном выключить лишние контейнеры (studio, pg_meta, analytics,
  edge_runtime, realtime).
- **Веб приложения горничной:** `cd apps/mobile && CI=1 npx expo start --web --port
  8090`; Chrome с `--lang=ru` и подменой `navigator.language` (иначе чешская
  локаль системы); кнопки — `[role="button"]` и текст (сначала равенство, потом
  вхождение), состояния — по `document.body.innerText`. В режиме `CI=1` правки не
  подхватываются — перезапуск. Камера в вебе — `<input type=file>`:
  `page.waitForFileChooser()`. Пароли тестовых учёток — не в репозитории;
  передавать переменной окружения, не файлом.
- **Панель на Vercel** гоняется напрямую: `networkidle0` не наступает (запросы к
  Supabase), ждать `domcontentloaded` и `waitForFunction(() =>
  !location.pathname.startsWith('/login'))`; поля входа `#email`, `#password`.
- **XLSX панели проверяется настоящим Excel** через COM из PowerShell
  (`New-Object -ComObject Excel.Application`, `Workbooks.Open`, `Range('C2').Value2`).
