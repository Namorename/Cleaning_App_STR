# Порядок заданий и уборок: день, затем объект (CORE, 27.11.2026)

Решение владельца 27.11: в списках заданий техников (`problems`) и уборок (`tasks`) строки идут
сначала по дню, затем по названию объекта по алфавиту. Одна функция в общем пакете —
`packages/shared/src/schedule/day-place-order.ts` (`orderByDayAndPlace`) и тонкие обёртки над ней:

| Обёртка | Где | Что внутри объекта |
|---|---|---|
| `orderQueue` (`problems/queue.ts`) | очереди заданий: живые, ранний день выше | срочность (критические выше), затем старше выше |
| `orderTaskHistory` (`problems/queue.ts`) | закрытые задания и архивы: поздний день выше | срочность, затем новее выше (как было) |
| `orderCleanings` (`day-place-order.ts`) | уборки | начало окна (`time_from`, без окна — в конце), затем время создания |

## Правило

1. **День** — как было в каждом списке, направление не меняется: очередь и предстоящие — ранний
   день выше, история («Закрытые», «Выполненные», архив) — поздний выше. На досках заданий (панель:
   «Открыто», «Назначено», «В работе»; телефон: доска главного техника и офиса) днём живого
   задания с работой считается **день техника**, который карточка показывает рядом с его именем
   (опция `workDay` у `orderQueue`); без работы — дата выполнения, иначе день создания. Поправка
   владельца 27.11 после выката («Задания не отсортированы»): колонка шла по дню создания, а его на
   карточке не видно.
2. **Объект** — по тому названию, которое показывает строка: дом, а у комнаты «дом — комната»
   (`propertyPathOf`, `cleaningPlace`). Сравнение — `Intl.Collator` языка интерфейса (en-GB, ru-RU,
   cs-CZ) с `numeric: true, sensitivity: 'base'`: без учёта регистра и диакритики, числа по значению
   («Apt 2» раньше «Apt 10», «3-302» раньше «3-3008»), чешское «ch» после «h».
3. **Без объекта** (объект не прочитан или пустое название) — в конце своего дня.
4. **Дальше** — только между строками одного объекта (таблица выше).

Строка, сохранённая на телефоне старой сборкой, без новых полей (`created_at` у уборки, название у
объекта задания) сортируется так же, недостающее считается неизвестным; ничего не падает.

## Где применено

Панель:
- «Задания»: колонки доски «Задания техников» (живые — очередь по дню техника, без работы — по дате
  выполнения или дню создания; «Выполнено» — по дню закрытия, новые выше), список (живые по дате
  выполнения или дню создания — строка показывает «Сообщено», не день техника; затем закрытые по
  дню создания, новые выше), архив (по дню создания, новые выше).
- «Уборки»: вкладка «Сегодня» — хвосты прошлых дней (ранний день выше) и части дня (утро, день,
  вечер, без времени) остаются заголовками, внутри каждой — по объекту; «Предстоящие» и «Закрытые» —
  внутри каждого дня по объекту.
- Календарь: ячейка свёрнутого дома (и окно «+N» с её уборками) — сначала уборки самого дома, затем
  его комнаты по названию, у каждой — по окну. В ячейке одного объекта объект один — по окну, затем
  времени создания.

Телефон:
- Задания: «Мои задания» техника (живые — очередь по дате выполнения или дню создания: карточка
  показывает время сообщения, дня работы в строке нет; «Запланировано» как было, закрытые — по
  дню, новые выше), доска главного техника и офиса (живые — очередь по дню ремонта, который
  показывает карточка, без ремонта — по дате выполнения или дню создания; закрытые и архив — по
  дню, новые выше).
- Уборки: «Мои» (блоки «В работе», «Ремонт» и дни), «Свободные», «Выполненные» (по дню
  завершения, новые выше), «Уборки» менеджера и день в календаре менеджера.

Сервер не менялся: страницы читаются от новых к старым (архивы, «Выполненные»), и следующая
страница добавляет только тот же или более ранний день, поэтому порядок по дню с ней не расходится;
внутри последнего дня строки встают по объекту. Остальные списки читаются целиком.

## Разделители по дням (CORE, 27.11)

Промпт владельца 27.11: в колонках доски «Задания техников» перед первой карточкой каждого нового
дня — ненавязчивый разделитель. Общий компонент `apps/web/src/components/day-divider.tsx`
(`DayDivider`) и чистая функция `apps/web/src/lib/day-entries.ts` (`withDayHeadings`: вставляет
заголовок перед первым элементом нового дня, ничего не переставляет).

- **Вид**: мелкая (12 px) приглушённая подпись без жирности и тонкая линия цвета рамок темы до
  края колонки; без рамок, фона и значков. Над разделителем 16 px, под ним 8 px — подпись ближе к
  своим карточкам; у первого в колонке верхнего отступа нет. Светлая и тёмная темы — через
  токены `muted-foreground` и `border`.
- **Подпись** — Intl языка интерфейса: «Сегодня · пт 27.11», «Завтра · сб 28.11», «вс 29.11»,
  прошлые дни — «чт 26.11» (en: «Today · Fri 27/11», cs: «Dnes · pá 27. 11.»); год — только у дня
  не этого года («сб 25.10.2025»). «Сегодня» — по поясу объекта первой карточки дня, как у
  карточек.
- **День** — тот же, по которому колонка сортирована (`columnDay` в `features/problems/order.ts`):
  живые — день техника, без работы — дата выполнения, иначе день создания; «Выполнено» — день
  закрытия, новые выше.
- **Доступность**: заголовок `h2`; экранный чтец слышит день полностью («Сегодня, пятница,
  27 ноября»), короткая подпись и линия от него скрыты. Фокуса и обработчиков нет,
  `pointer-events: none` — перетаскивание и клики проходят к колонке, порядок фокуса по
  карточкам прежний. Разделитель позиционирован (`relative`): полная подпись для чтеца лежит в
  `sr-only` (`position: absolute`), и без этого в прокручиваемой колонке она «висела» на странице и
  удлиняла её на тысячи пикселей (баг 28.11, `docs/rollout/board-height-1128.md`).
- **Число карточек дня не показано**: в колонке с одним днём оно повторяло бы число в заголовке
  колонки, а в «Выполнено» с «Показать ещё» было бы неясно, всех ли карточек дня оно касается.
- **«Список»** заданий тоже идёт по дням без заголовков — получил тот же разделитель строкой на
  всю ширину таблицы (`listDay`: живые — дата выполнения или день создания, закрытые — день
  создания; закрытая часть начинает дни заново). Линия разделителя — единственная между днями:
  строка над ним своей нижней линии не рисует. «Показать ещё» пропускает строки-разделители.
- Не менялись: архив, телефон, база, функции, API. Доски менеджеров получили разделители 28.11
  (ниже).
- **Доски менеджеров** (промпт 28.11, CORE, только панель): тот же `DayDivider` и тот же
  `withDayHeadings` в каждой колонке каждой доски и в «Назначено мне» (`ManagerBoard`,
  `features/boards/card-days.ts`). День карточки — её **срок** (`due_on`): другой даты у карточки
  доски нет. Порядок прежний и общий с телефоном (`orderCards`): «По сроку» — уже «день, внутри дня
  новые выше», карточки без срока — в конце колонки под строкой «Без срока» (`boards.noDue`). В
  порядке «Новые сверху» колонка идёт не по дням, и линий нет: они резали бы список через карточку.
  Линии — не карточки: не перетаскиваются, не считаются; карточка, брошенная поверх линии, ложится
  в её колонку, как раньше. Проверено: разметка доски из vitest в настоящей оболочке панели и с её
  CSS в Chrome — страница ровно в окно от `md` (1280 × 700 … 1920 × 1080, 125 %), все линии внутри
  прокручиваемых колонок.

## Где оставлено как было

- Собственные сообщения горничной о поломках («Мои задания» горничной) — это не очередь техника, в
  запросе не названа; новые выше, как было.
- Порядок карточек досок менеджеров (`orderCards`; линии по дням у них с 28.11 — выше), порядок
  колонок досок, счётчики и сводки (дашборд:
  «Зависшие ремонты», «Работа без сотрудника»; утренняя сводка — только числа, списка нет).
- Ремонты задания на его странице, работы и задания на карточке объекта (`property_problems`,
  `property_maintenance_tasks`), задания объекта у отзыва и у плана — список одного объекта по дате,
  порядок задают функции БД (правка была бы миграцией).
- Публичный API v1 и MCP (`api_v1_list_tasks`, `api_v1_list_cleanings`): их страницы привязаны к
  своему порядку.
- «Не состоялась» в календаре — без времени, в конце своей ячейки, как было.
